# Lexi как Telegram Mini App

Документ для выпуска и поддержки: настройка ботов, границы облачной синхронизации, копии, офлайн, откат и матрица проверок на реальных устройствах. Секретов здесь нет и быть не должно: токен бота живёт только в BotFather и не нужен ни клиенту, ни сборке.

## Боты и адреса

| Назначение | Бот | Адрес Mini App | Ссылка запуска |
|---|---|---|---|
| Выпуск | `@TaveloriBot` | `https://tavelori.app/` | `https://t.me/TaveloriBot?startapp` |
| Разработка и приёмка | `@TaveloriDevBot` | HTTPS-туннель или тестовая сборка с параметром `?bot=TaveloriDevBot` | `https://t.me/TaveloriDevBot?startapp` |

Имя бота передаётся приложению параметром `?bot=<username>` в адресе Mini App. Без параметра приложение считает, что запущено из `@TaveloriBot`. Параметр нужен только для разделения локальных профилей: CloudStorage сам по себе разделён по ботам, а локальная база — по паре «бот + пользователь» (`lexi-tg-<бот>-<id>`). Обычный браузер использует базу `lexi`.

Статус реквизитов (задача 0.1): доступ к обоим ботам, два устройства (iOS и Android) и постоянный адрес первой версии подтверждаются владельцем; по умолчанию адрес остаётся текущим GitHub Pages, переезд на другой хостинг не выполняется.

## Настройка Main Mini App в BotFather

1. Открыть `@BotFather` → `/mybots` → выбрать бота → **Bot Settings** → **Configure Mini App** (в старых версиях: **Menu Button** / **Main App**).
2. Включить Main Mini App и указать адрес из таблицы выше. Для бота разработки — адрес туннеля с `?bot=TaveloriDevBot`, см. `docs/telegram-dev.md`.
3. При желании задать короткое имя и описание; они не влияют на приложение.
4. Проверить запуск из профиля бота (кнопка **Open** / **Открыть**) и по прямой ссылке `https://t.me/<бот>?startapp`. В обоих случаях должен открыться экран «Сегодня».

Что приложение получает от Telegram: параметры запуска в hash (`tgWebAppData`, `tgWebAppPlatform`, `tgWebAppVersion`). Они используются только для интерфейса и выбора локального профиля. Никакой серверной проверки `initData` нет, потому что сервера нет; при появлении сервера проверка обязательна.

Что приложение **не** запрашивает: номер телефона, доступ к сообщениям, контакты, платежи, отдельный аккаунт. Обработчик `/start` и webhook не нужны: бот служит только точкой запуска.

## Откат

- Быстрый: в BotFather отключить Main Mini App или вернуть адрес предыдущей проверенной сборки. Данные пользователей остаются в их устройствах и в CloudStorage.
- Сборка для отката должна понимать локальную схему 6 (текущая). Более старый клиент откроет базу с новой схемой с ошибкой Dexie; поэтому откатываться ниже версии со схемой 6 нельзя без полной копии. Автоматического отката базы нет: приложение не удаляет базу и не подменяет её старой копией — исправление поставляется вперёд совместимым клиентом, а экспорт полной копии остаётся доступным.
- Если облако содержит версию более нового формата снимка, старый клиент не применяет и не перезаписывает её, а показывает «обновите приложение»; локальные данные не теряются.

## Границы облачной синхронизации

Через Telegram CloudStorage одного пользователя и одного бота синхронизируется **компактный прогресс**:

- состояния FSRS поставляемых карточек обоих видов — слов и фраз (сроки, стабильность, повторы);
- компактное состояние навыков для выбора упражнения: исходы последних десяти ответов каждого типа, два последних типа, число чистых сборок перед письмом;
- настройки: часовой пояс, размер занятия; темп курса — дневной предел новых карточек и расписание;
- даты и статусы стандартных уроков, список установленных стандартных пакетов;
- сводная статистика: последние 14 дней (ответы и карточки), последние исходы по типам проверки, итоги.

Тексты карточек, введённые ответы и описания учебной цели в облако не уходят: `target` поставляемой карточки приходит с её пакетом.

Остаётся локальным и переносится только полной копией: полная история ответов, незаконченное занятие с позицией, пользовательские слова и наборы, правки стандартных слов, личные картинки и аудио.

Состояния карточек, пакет которых на этом устройстве ещё не установлен, сохраняются отложенно: они не участвуют в обучении и становятся обычным прогрессом после установки пакета.

Веб и Telegram — независимые профили даже на одном устройстве и одном адресе. Веб не показывает вход через Telegram и не вызывает CloudStorage. Ручной перенос копией не создаёт связи между профилями: следующие ответы снова независимы.

### Как устроены версии

Каждая установка получает случайный идентификатор устройства. Устройство пишет только свои ключи: неизменяемые части поколения `v_<версия>_<n>` (до 4000 символов каждая) и собственный указатель `p_<устройство>`, публикуемый последним. Версия несёт причинную базу (вектор счётчиков устройств), контрольную сумму и список разрешённых ветвей. Время не участвует в выборе победителя.

Обмен: при открытии, возврате в приложение, через две секунды после локальных изменений, при восстановлении сети и по кнопке «Повторить» на экране «Ещё». Ошибки повторяются с растущей задержкой (30 с → 10 мин), не бесконечным циклом.

Решения координатора:

| Ситуация | Действие |
|---|---|
| Облачная версия причинно новее, локальных изменений нет | Применить целиком одной транзакцией |
| Локальная версия продолжает известную облачную | Опубликовать |
| Независимые изменения здесь и там | Конфликт: пользователь выбирает целую версию |
| Первое подключение непустой локальной базы к непустому облаку | Выбор состояния, без автоматической перезаписи |
| Восстановлена полная копия при наличии облака | Выбор между восстановленным и облачным |
| Версия неизвестного формата | Не применять, не публиковать, предложить обновить |
| Нет места (1024 ключа) | Остановить запись, сохранить очередь локально |

Отвергнутые версии сохраняются на устройстве («Копия данных» → «Отложенные версии облака»), их можно сохранить файлом и удалить вручную. Автоматически чужие или конфликтные ключи не удаляются; устройство очищает только собственные устаревшие поколения после успешной публикации.

Статусы в интерфейсе: «Сохранено на устройстве», «Синхронизация…», «Синхронизировано · время последнего подтверждённого обмена», «Ошибка синхронизации», «Конфликт версий», «Синхронизация приостановлена» (нет сети, другая вкладка или нет Web Locks). Время подтверждения не означает отсутствия новых изменений на другом устройстве.

## Копии и файлы в WebView

Сохранение копии идёт через `navigator.share` с файлом, если клиент его поддерживает, иначе через обычное скачивание. Статус говорит «файл передан…», а не «сохранён»: браузер не сообщает о фактическом сохранении. Отмена диалога — отдельный статус, данные не меняются. Перед заменой данных копией защитная копия обязана уйти; отмена или ошибка передачи останавливают замену.

Копия из Telegram-профиля имеет имя базы `lexi-tg-<бот>-<id>` и восстанавливается в браузере обычным способом (и наоборот). Служебные ключи синхронизации (идентификатор устройства, очередь) в копию не входят и при восстановлении не перезаписываются.

## Офлайн

Уже открытое приложение продолжает работать со скачанными уроками при потере сети; ответы сохраняются локально, синхронизация ждёт сети. Повторный запуск Mini App без сети зависит от клиента Telegram, и приложение его не обещает. В браузере и PWA офлайн-гарантия для скачанных уроков сохраняется. WebView без service worker или storage API работает онлайн; экран «Ещё» показывает «Офлайн-кеш недоступен в этом клиенте».

## Отчёты о сбоях

Сервера у приложения нет, поэтому о сбоях у пользователей владелец узнаёт из Sentry (проект `tavelori`, организация `storewizard`). Внутри Telegram каждое событие несёт метки `env=telegram`, `tg.version` и `tg.platform` из параметров запуска, `app.version` и `app.build`, а крошки `lexi.lifecycle` фиксируют `activated`, `deactivated`, `viewportChanged` и `visibilitychange` с высотами области просмотра — ровно тот контекст, которого не хватало для белого экрана после сворачивания (#2). `initData`, идентификатор и имя пользователя модуль отчётов не читает; адреса режутся до пути, поэтому `#tgWebAppData` в отчёт не попадает. Границы канала описаны на экране «Копия данных», переключатель — в «Настройках». Полный список правил — в `openspec/specs/error-reporting/spec.md`.

Адрес приёма приходит из переменной репозитория `VITE_SENTRY_DSN` только в workflow публикации; тестовая и локальная сборки его не получают и запросов к сервису не делают. Релиз называется `lexi@<версия>+<коммит>`, карты кода загружаются в Sentry секретами `SENTRY_AUTH_TOKEN`, `SENTRY_ORG`, `SENTRY_PROJECT` и удаляются из `dist` до публикации.

## Аудио и клавиатура

Отказ воспроизведения показывается в упражнении «Что прозвучало?» с кнопками «Повторить» и «Продолжить без аудио». Пропуск не создаёт события и не меняет интервалы. При скрытии приложения звук останавливается. Системный греческий голос не обещается на каждой платформе; без файла и голоса аудирование для слова не предлагается.

Док занятия следует за устойчивой высотой Telegram (`viewportStableHeight`) и за видимой областью `VisualViewport` при открытой клавиатуре; ширины 360 и 390 пикселей проверены браузерным тестом без горизонтальной прокрутки.

## Режимы запуска

BotFather позволяет выбрать Launch Mode: Compact, Fullsize или Fullscreen. Приложение работает во всех трёх и не требует полного экрана. Текущий режим определяется по `isFullscreen`/`isExpanded`, обновляется по событию `fullscreenChanged`, виден стилям в атрибуте `data-launch-mode` на `<html>` и показан на экране «Ещё» вместе с платформой и версией клиента. Во весь экран поверх контента лежат системная строка и кнопки «Закрыть» и «…» клиента; их высоту приложение берёт из `safeAreaInset` и `contentSafeAreaInset` и добавляет к верхнему отступу экранов без шапки, шапок с заголовком и занятия. Системный `env(safe-area-inset-*)` при этом не суммируется с отступами Telegram.

## Сворачивание и возврат

С Bot API 8.0 Mini App можно свернуть в полосу внизу чата и вернуть касанием. Клиент присылает `deactivated` при сворачивании и `activated` при возврате, состояние отражает `WebApp.isActive`; пока приложение спит, клиент может сменить тему и отдать нулевые размеры. Приложение подписано на оба события, а для клиентов без Bot API 8.0 использует видимость документа (`visibilitychange`). На возврат обоими путями оно перечитывает тему, устойчивую высоту и безопасные отступы, обновляет переменные оболочки и атрибуты `<html>`, чем заставляет WebView пересчитать стили и перерисовать экран; состояние упражнения при этом не трогается. Активность видна в атрибуте `data-app-active` на `<html>`. Нулевая или неизвестная высота не отменяет последнюю положительную: `--app-height` держит прежнее значение, поэтому экран занятия не схлопывается в полосу. Подписка на события, которых клиент не знает, запуску не мешает.

Найденная причина белого экрана (issue #2, iPhone, 17.09.2026, dev-сборка): после нескольких циклов сна WebKit отвечает на чтение IndexedDB ошибкой `UnknownError: Attempt to get a record from database without an in-progress transaction`. Живой запрос Dexie передаёт её в рендер, а без корневой границы ошибок React снимает всё дерево — страница пустая до полного закрытия. Теперь над приложением стоит граница восстановления: ошибку хранилища она лечит переоткрытием базы и перемонтированием экранов без перезагрузки и без потери раздела; после трёх сбоев подряд за минуту или при любой другой ошибке показывает «Не удалось показать экран» с кнопкой «Перезапустить» и уверением, что данные сохранены. Сам дефект WebKit приложение не лечит.

Отдельно известны дефекты самих клиентов (свёрнутый Mini App не открывается с первого касания, белый экран из-за Android System WebView или повреждённого кеша) — они не связаны с приложением. Проверка на реальных устройствах остаётся в матрице отдельной строкой; браузерные тесты проверяют поведение приложения на события bridge и на подменённый отказ IndexedDB.

## Главное действие на «Сегодня» (задача 0.5)

Решение не принято: прототип на двух реальных устройствах не выполнялся. По правилу из дизайна первый выпуск сохраняет обычную кнопку Lexi «Начать/Продолжить занятие». Контракт нативного действия (текст, loading/disabled, замена обработчика, снятие при уходе) реализован в платформенном адаптере и покрыт unit-тестом, но на экране не включён. Снимки экранов и решение записать сюда после прототипа.

## Выпуск

1. `npm test`, `npm run test:e2e`, `npm run build` зелёные (production собирается с корневым `BASE_PATH=/`, который CI берёт из настроек GitHub Pages).
2. `@TaveloriDevBot` указывает на тестовую сборку; матрица выше заполнена версиями и результатами для iOS и Android; блокирующие дефекты исправлены.
3. Сборка опубликована на `https://tavelori.app/`; в BotFather для `@TaveloriBot` включён Main Mini App с этим адресом.
4. Проверены запуск из профиля, `https://t.me/TaveloriBot?startapp` и обычный веб-адрес; записаны версия выпуска (commit) и способ отката.
5. В Sentry появился релиз `lexi@<версия>+<коммит>` с картами кода; тестовое событие из опубликованной сборки показывает читаемый стек.
