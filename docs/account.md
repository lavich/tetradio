# Аккаунт и изоляция данных

Владелец локальных данных — пара «бот + Telegram-пользователь». Регистрации, браузерного и анонимного профиля нет.

| Запуск | Что происходит | База IndexedDB |
| --- | --- | --- |
| Telegram, `user` в initData | приложение, синхронизация через CloudStorage | `tetradio-tg-<bot>-<id>` |
| Telegram без `user` (или ID не определяется) | экран «Не удалось определить аккаунт», ничего не читается и не отправляется | не открывается |
| Обычный браузер, production | экран «Откройте в Telegram» со ссылкой на `VITE_TELEGRAM_BOT` (без переменной — текст без ссылки) | не открывается |
| Обычный браузер, сборка с `VITE_TELEGRAM_MOCK=<id>` | приложение под тестовым пользователем, без облака | `tetradio-mock-<id>` |

- Контекст запуска берётся из hash адреса (`tgWebAppData`), как его передаёт Telegram. Новый запуск заменяет контекст,
  сохранённый во вкладке (`sessionStorage`, ключ `tetradio:launch`); без hash контекст восстанавливается только для
  перезагрузки той же вкладки.
- После загрузки bridge владелец сверяется с `Telegram.WebApp.initDataUnsafe.user.id`. Расхождение останавливает запуск
  экраном ошибки, сохранённый контекст стирается, синхронизация не подключается.
- Данные других баз на устройстве (прежняя браузерная `tetradio`, другие аккаунты) не читаются и не предлагаются к
  переносу. Перенос — только полной копией на экране «Копия данных»; владельцем восстановленных данных становится
  текущий пользователь: имя базы и служебные ключи `sync:*` из файла не используются. Если после предпросмотра копии
  другое устройство опубликовало новую версию в CloudStorage, замена отменяется до изменений и требует нового
  предпросмотра (подробно — [design.md](../openspec/changes/archive/2026-10-01-course-progress-sync/design.md), «Резервная копия»).
- Мок включается только флагом сборки: `npm run dev:mock`, e2e (`playwright.config.ts`, `playwright.course.config.ts`)
  и unit-тесты (`vite.config.ts` → `test.env`). Деплой на GitHub Pages собирается с пустым `VITE_TELEGRAM_MOCK`.
  Сборка e2e кладёт рядом production-вариант без мока в `.e2e/mechanics/dist/web/` — на нём проверяется экран «Откройте в Telegram».

Код: `src/platform/launch.ts` (контекст запуска), `src/storage/profile.ts` (владелец и имя базы), `src/storage/db.ts`
(база без владельца не открывается), `src/main.tsx` и `src/app/LaunchGate.tsx` (экраны остановленного запуска).
Тесты: `tests/profile.test.ts`, `tests/e2e/account.spec.ts`.

## Удаление данных

«Настройки и данные» → «Удаление данных» → «Удалить мои данные…» (`src/features/backup/DeleteData.tsx`, `src/storage/erase.ts`). В сессии: проверка облака (в Telegram нужен мост с CloudStorage, Bot API 6.9+ и владелец моста, совпадающий с профилем — иначе отказ без каких-либо удалений); при галочке «И переписку с автором» — `POST /forget` Worker-а (тема в группе поддержки и запись D1; у заблокированного остаётся отметка); загрузка модуля синхронизации и `sync.halt` — обмен остановлен, блокировка синхронизации держится до конца облачного шага; отметка `tetradio:erasing:<база>` = `cloud`; все ключи CloudStorage бота (`p_` → `cp_` → `v_` → прочие); отметка `local`; перезапуск на `app/`. Сбой до конца облачного шага — сообщение, отметка снимается, синхронизация возвращается (`sync.resume`).

Устройство очищается при запуске с отметкой (`main.tsx` → `resumeErase`): база и SDK отчётов ещё не открыты — в той же вкладке SDK держит свою базу открытой и удалить её нельзя. Удаляются очередь отчётов, база приложения и `tetradio-restore`, ключи профиля в `localStorage` (`tetradio:haptics:<база>`, черновик сообщения, подсказка) и `scroll:*` в `sessionStorage`; затем перезапуск. Остаются `tetradio:launch`, `__telegram__*` (параметры моста), `tetradio:start-consumed` и служебные записи. Фаза `cloud` при запуске (прервали во время облачного шага) — после моста, без облака — «Повторить» / «Отменить удаление»; база не удалилась — «Закройте другие окна…», отметка остаётся. Пока отметка стоит, обмен любой вкладки не публикует. Другие устройства удаление не видят: на них его нужно повторить, иначе они снова опубликуют свой прогресс.
