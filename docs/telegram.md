# Τετράδιο как Telegram Mini App

Настройка бота, разработка внутри Telegram, поведение в WebView, откат и проверки на реальных устройствах. Синхронизация прогресса — [sync.md](sync.md), владелец данных и изоляция аккаунтов — [account.md](account.md). Секретов здесь нет: токен бота хранится в BotFather и нужен только владельцу для регистрации вебхука.

## Бот и адрес

Выпуск — [@TetradioBot](https://t.me/TetradioBot), Main Mini App `https://tetradio.app/app/`, лендинг — `https://tetradio.app/` (GitHub Pages, `.github/workflows/deploy.yml`). Домен зарегистрирован в Cloudflare: записи `@` и `www` — CNAME на `lavich.github.io` без проксирования (иначе GitHub не выпустит сертификат), TXT `_github-pages-challenge-lavich` подтверждает домен за аккаунтом. Старый адрес `lavich.github.io/tetradio/` GitHub перенаправляет на домен. Имя бота сборка получает из `VITE_TELEGRAM_BOT`.

Параметр адреса `?bot=<имя>` задаёт бота для локального профиля (`tetradio-tg-<бот>-<id>`): так бот разработки на том же устройстве не смешивает данные с основным. CloudStorage у разных ботов и так раздельный.

Лендинг и приложение — две страницы одной сборки (`index.html` и `app/index.html`). Лендинг статичный: плагин `landing-page` в `vite.config.ts` при сборке и в dev вписывает в `index.html` разметку из собранного контента (`src/landing/render.ts`), а `src/landing/main.ts` без React добавляет полку и пробный урок; переход из Telegram в `app/` — встроенный скрипт в `<head>`, до первого кадра. Главная, открытая внутри Telegram (старый адрес Mini App), сразу переходит в `app/` с теми же параметрами запуска; `app/` в обычном браузере уходит на лендинг. Service worker и манифест PWA — только в области `app/`; регистрацию на весь сайт, оставшуюся от прежних версий, снимают и лендинг, и приложение. Глубокие адреса `app/...` на GitHub Pages открывает `404.html` — копия `app/index.html`.

Настройка в BotFather: `/mybots` → бот → **Bot Settings** → **Configure Mini App** → включить Main Mini App и указать адрес. Проверить запуск из профиля бота (**Open**) и по ссылке `https://t.me/<бот>?startapp` — открывается «Сегодня».

Ссылки внутрь приложения (`src/platform/launch.ts`, `src/platform/share.ts`): `https://t.me/<бот>?startapp=w_<id слова>` открывает слово, `https://t.me/<бот>?startapp=c_<id курса>` (например, `c_english-travel`) — «Курс» с полкой этого курса (у неначатого — с его карточкой); курс только показывается, не начинается и основным не становится. Неизвестный параметр или курс, которого нет в каталоге (в том числе скрытый флагом `hidden: true`), открывает «Сегодня»; так же — слово скрытого курса. Ссылку на слово даёт «Поделиться словом» на листе слова, на курс — «Поделиться курсом» на полке начатого курса. Тот же запуск после автообновления ссылку второй раз не открывает.

Приложение получает от Telegram параметры запуска в hash (`tgWebAppData`, `tgWebAppPlatform`, `tgWebAppVersion`) и использует их для интерфейса и выбора профиля; подпись `initData` проверяет только Worker бота — для формы «Написать автору» (раздел «Бот и обратная связь»). Номер телефона, контакты и платежи не запрашиваются. На `/start` и сообщения боту отвечает отдельный Worker — раздел «Бот и обратная связь»; приложение от него не зависит.

## Политика конфиденциальности

`https://tetradio.app/privacy/` (русская, главная) и `/privacy/en/` — статические страницы `privacy/` без скриптов и хранилищ, вне service worker. Ссылки: в конце лендинга и последней строкой «Настроек и данных» (`openLink` в Telegram с Bot API 6.1+, иначе новая вкладка). В BotFather: `/mybots` → бот → **Bot Settings** → **Privacy Policy** → `https://tetradio.app/privacy/`. Перечень полей и меток отчёта в политике сверяет `tests/privacy-page.test.ts` с `ALLOWED_EXTRA` и `REPORT_TAGS`; при изменении того, что приложение, бот или форма хранят и передают, текст правится вместе с кодом.

## Бот и обратная связь

`bot/` — Cloudflare Worker `tetradio-bot` на `*.workers.dev`, вебхук @TetradioBot. Тело обновлений и тексты сообщений не логируются, Workers Logs выключены; сообщения боту проходят через Cloudflare.

**Пользователю.** На `/start` (и `/start <параметр>`) — приветствие с кнопкой `web_app` «Открыть Τετράδιο» (`APP_URL`). На `/start feedback` и `/start fb_<id отчёта>` (кнопки «Написать автору» в «Настройках» и на экране сбоя, `src/platform/feedback.ts`) — «Напишите сообщение: вопрос, ошибку в уроке или идею. Можно приложить скриншот.» Любое другое сообщение копируется в тему пользователя в группе поддержки; пользователь получает «Сообщение передано автору, ответ придёт сюда.» раз в сутки, на остальные сообщения — реакцию 👍; при сбое — «Не удалось передать сообщение. Попробуйте позже.». Всё, что получает пользователь, возвращается в теле ответа на вебхук и не требует токена: неверный или отозванный токен не делает бота немым.

**Форма в приложении.** «Написать автору» в «Настройках» и на экране сбоя раскрывает форму на месте (`src/features/feedback/`, код формы грузится по нажатию): поле до 3000 символов, «Отправить», ссылка «Приложить скриншот — в чате с ботом» (прежний переход `?start=feedback`/`fb_<id>`). Перед отправкой — `requestWriteAccess` (если подписанный `allows_write_to_pm` ещё не разрешает; старый клиент, исключение или 30 секунд без ответа — считаем, что можно; ответ запоминается до конца запуска). Запрос — `POST /feedback` Worker-а с `Content-Type: text/plain` (простой запрос без `OPTIONS`): `initData`, текст, версия, платформа, id отчёта, `canReply`. Worker проверяет подпись `initData` токеном бота (`bot/form.ts`, срок `auth_date` — 7 суток), адрес страницы (`APP_ORIGINS`), формат полей и частоту (не чаще раза в 10 секунд — `form_at` в D1, слот занимается до доставки), и пишет в тему «Из приложения · <версия> · <платформа>», при отказе в разрешении — «ответить нельзя: бот не может писать пользователю», затем текст. Ответы: 200, 400 `invalid`, 401 `stale`, 429 `rate`, 502/503 `failed`; у приложения на них свои тексты, черновик хранится в `localStorage` до успешной отправки. Форма есть только в Telegram основного бота при заданном в сборке `VITE_FEEDBACK_URL` (переменная репозитория, `deploy.yml`) и мосте с `initData`; иначе кнопка открывает чат, как раньше. Доступность проверяется в момент нажатия — экран отказа базы появляется раньше моста. Если код формы не загрузился, вместо неё — переход в чат.

**Автору.** Группа поддержки — супергруппа «Τετράδιο — поддержка» (`SUPPORT_CHAT_ID` в `bot/wrangler.jsonc`) с включёнными темами; бот — администратор с правом «Управление темами». На каждого пользователя — тема: первым сообщением имя, @username, id и язык Telegram, перед сообщением после `/start fb_<id>` — ссылка на событие Sentry (`SENTRY_EVENT_URL`). Сообщение в теме, своё или анонимное от имени группы, копируется пользователю от имени бота без подписи; отказ Telegram (пользователь заблокировал бота) — «Не доставлено: …» в теме. `/block` и `/unblock` в теме прекращают и возобновляют приём от пользователя; прочие сообщения с `/` пользователю не уходят. Общая тема, служебные сообщения и другие боты пропускаются.

Ограничения: правки сообщений не доходят ни в тему, ни пользователю (`edited_message` не принимается); ответ приходит пользователю без цитаты его сообщения; у бота разработки (`?bot=`) Worker нет; около 20 сообщений в минуту в группу — альбомы двух новых пользователей подряд могут получить «Не удалось передать».

**Хранение.** D1 `tetradio-feedback` (привязка `FEEDBACK`, миграции `bot/migrations/`): одна таблица `users` — id пользователя и темы, время последнего текстового подтверждения, блокировка, id отчёта Sentry на сутки, время последней формы. Записи точечные — каждая меняет свои столбцы: форма и вебхук пишут одну строку параллельно. Текстов нет; переписка хранится в группе Telegram. Вебхук зарегистрирован с `max_connections: 1`: обновления приходят по одному, альбом нового пользователя не создаёт несколько тем.

**Без настройки.** Пока у Worker нет `BOT_TOKEN`, `SUPPORT_CHAT_ID` или `FEEDBACK`, бот отвечает как раньше: приветствием на любой `/start` и «Сообщения боту пока не читаются. Τετράδιο открывается кнопкой ниже.» на остальное.

**Выкатка.** Зависимости Worker — `bot/package.json` со своим lock-файлом: `wrangler` не попадает в зависимости приложения. CI собирает Worker без выкатки (задача `worker` в `ci.yml`); `deploy.yml` выкатывает его после зелёного CI на `main` в окружении GitHub `cloudflare` с правилом ветки `main`. `CLOUDFLARE_API_TOKEN` (право `Workers Scripts: Edit`; выкатка с привязкой D1 проверена первой выкаткой) и `CLOUDFLARE_ACCOUNT_ID` — секреты этого окружения, не репозитория: секрет репозитория читает любой workflow любой ветки. Без токена шаги пропускаются с предупреждением в Actions, сайт выкатывается как обычно. Зависимости `bot/` Dependabot обновляет раз в месяц.

Настройка — после первой выкатки Worker из CI (иначе `secret put` предложит создать пустой Worker); `wrangler` авторизуется через `npx --prefix bot wrangler login` или `CLOUDFLARE_API_TOKEN` в окружении:

```sh
npx --prefix bot wrangler d1 migrations apply tetradio-feedback --remote --config bot/wrangler.jsonc   # схема — до выкатки кода
openssl rand -hex 32                                                    # секрет вебхука: только A-Z, a-z, 0-9, _ и -
npx --prefix bot wrangler secret put WEBHOOK_SECRET --config bot/wrangler.jsonc
# .env.bot (в .gitignore, значения без кавычек): BOT_TOKEN, WEBHOOK_URL=https://tetradio-bot.<поддомен>.workers.dev/, WEBHOOK_SECRET
sed -n 's/^BOT_TOKEN=//p' .env.bot | npx --prefix bot wrangler secret put BOT_TOKEN --config bot/wrangler.jsonc
node --env-file=.env.bot scripts/bot-webhook.ts                         # setWebhook (max_connections: 1), затем getWebhookInfo
```

id группы — из адреса группы в web.telegram.org (`#-100…`). Скрипт печатает адрес вебхука, число ожидающих обновлений, число соединений и последнюю ошибку доставки; токен в вывод не попадает. Повторный запуск безопасен.

Откат: `npx --prefix bot wrangler rollback <версия> --config bot/wrangler.jsonc` — на конкретную версию из `wrangler deployments list` (каждый `secret put` создаёт новую версию, «предыдущая» может оказаться той же сборкой); `node --env-file=.env.bot scripts/bot-webhook.ts --delete` — бот молчит. Утечка токена Cloudflare или `BOT_TOKEN` даёт писать от имени бота: `/revoke` в BotFather, новый `BOT_TOKEN`, перерегистрация вебхука, отзыв токена Cloudflare.

## Разработка внутри Telegram

CloudStorage, BackButton, тема и клавиатура настоящего клиента проверяются только в Telegram, а он открывает Mini App лишь по HTTPS. Локальный сервер выводится наружу туннелем:

```sh
npx --yes cloudflared tunnel --url http://localhost:5173   # или ngrok http 5173
TUNNEL_HOST=<имя>.trycloudflare.com npm run dev            # vite.config.ts пускает только этот hostname
```

В BotFather у бота разработки указать `https://<имя>.trycloudflare.com/?bot=<бот разработки>`. IndexedDB привязана к origin: новый адрес туннеля — пустая база. Прогресс вернётся из CloudStorage после первого обмена, полная история — только полной копией; для долгой работы удобнее постоянный адрес (именованный туннель).

Инспекция:

- **iOS** — Telegram: Настройки → десять нажатий на иконку настроек → Debug Settings → **Allow Web View Inspection**; на Mac — Safari → Разработка → устройство.
- **Android** — Telegram: Настройки → долгое нажатие на версию → Debug Menu → **Enable WebView Debug**; на компьютере — `chrome://inspect#devices`.
- Параметры запуска — `sessionStorage['tetradio:launch']`, статус синхронизации и режим запуска — на экране «Прогресс», ключи облака — `Telegram.WebApp.CloudStorage.getKeys(console.log)`.

## Поведение в WebView

**Режимы запуска.** Приложение работает в Compact, Fullsize и Fullscreen. Режим берётся из `isFullscreen`/`isExpanded`, обновляется по `fullscreenChanged` и виден в атрибуте `data-launch-mode` на `<html>`. Во весь экран к верхнему отступу добавляются `safeAreaInset` и `contentSafeAreaInset` клиента.

**Сворачивание и возврат** (Bot API 8.0). Клиент присылает `deactivated`/`activated`; в старых клиентах — `visibilitychange`. На возврат приложение перечитывает тему, устойчивую высоту и отступы; состояние упражнения не трогается. Активность — атрибут `data-app-active`. Нулевая высота не отменяет последнюю положительную: `--app-height` держит прежнее значение. После нескольких циклов сна WebKit может отказать IndexedDB (`UnknownError: … without an in-progress transaction`): граница восстановления переоткрывает базу без перезагрузки, после трёх отказов за минуту показывает «Не удалось показать экран» с «Перезапустить».

**Офлайн.** Открытое приложение работает со скачанными уроками без сети; ответы сохраняются локально, синхронизация ждёт сети. Повторный запуск Mini App без сети зависит от клиента Telegram. Без service worker «Прогресс» показывает «Офлайн-кеш недоступен в этом клиенте».

**Копия данных.** Файл передаётся через `navigator.share`, если клиент его поддерживает, иначе скачиванием; статус говорит «передан», а не «сохранён». Перед заменой данных защитная копия обязана уйти: отмена или ошибка останавливают замену.

**Отчёты о сбоях.** Sentry, только при заданном `VITE_SENTRY_DSN` в workflow публикации. События несут метки `env`, `tg.version`, `tg.platform`, `app.version`, `app.build` и крошки `tetradio.lifecycle`; `initData`, идентификатор и имя пользователя не читаются, адреса режутся до пути. Релиз — `tetradio@<версия>+<коммит>`, карты кода загружаются секретами `SENTRY_*` и удаляются из `dist`.

## Откат

- Быстрый: в BotFather вернуть адрес предыдущей проверенной сборки или отключить Main Mini App. Данные остаются на устройствах и в CloudStorage.
- Сборка для отката должна понимать базу Dexie v9 и облачные форматы, которые уже лежат в облаке. Более старый клиент не откроет базу новой версии, а облачную версию нового формата не применит и не перезапишет («обновите приложение»). Исправления поставляются вперёд; полная копия остаётся доступной.
- **Формат 6 (сжатый снимок).** Откат — через сборку-цель: сборку с форматом 6, в которой `WRITE_FORMAT = 5` и `DECLARED_READS = [3, 4, 5]` (`src/sync/types.ts`). Она читает 6, при первом обмене снимает 6 из `reads` своего указателя, и остальные устройства по согласованию снова пишут 5 — без окна выбора. Она лечит только ошибки записи формата 6; ошибку чтения 6 лечит исправляющая сборка вперёд. На сборку до формата 6 — только когда все указатели `p_*` в облаке — `format: 5` и без 6 в `reads` (фрагмент ниже), то есть каждое устройство на сборке-цели уже опубликовало версию. Иначе откатанное устройство увидит «Обновите приложение», а его прежний указатель с 6 в `reads` продолжит разрешать запись 6.

Указатели облака — в консоли WebView (Safari Web Inspector, `chrome://inspect`):

```js
Telegram.WebApp.CloudStorage.getKeys((_, keys) =>
  Telegram.WebApp.CloudStorage.getItems(
    keys.filter((key) => key.startsWith("p_")),
    (_, items) =>
      console.table(
        Object.entries(items).map(([key, raw]) => {
          const pointer = JSON.parse(raw);
          return { key, id: pointer.id, format: pointer.format, reads: (pointer.reads || []).join(","), createdAt: pointer.createdAt };
        }),
      ),
  ),
);
```

Замер записи CloudStorage по одному и порциями (нужно 32 свободных ключа; тестовые ключи удаляются):

```js
(async () => {
  const storage = Telegram.WebApp.CloudStorage;
  const call = (method, ...args) =>
    new Promise((resolve, reject) => storage[method](...args, (error, value) => (error ? reject(error) : resolve(value))));
  const keys = Array.from({ length: 32 }, (_, index) => `bench_${index}`);
  const value = "x".repeat(4000);
  for (const batch of [1, 4, 8]) {
    const started = performance.now();
    for (let index = 0; index < keys.length; index += batch)
      await Promise.all(keys.slice(index, index + batch).map((key) => call("setItem", key, value)));
    console.log(`порциями по ${batch}: ${Math.round(performance.now() - started)} мс на ${keys.length} ключей`);
    await call("removeItems", keys);
  }
})();
```

Проверка автообновления: положить указатель формата новее приложения, уйти на «Сегодня» и подождать; после проверки удалить ключ. `reads` с 6 нужен, чтобы этот указатель не заставлял устройства 30 дней писать формат 5.

```js
Telegram.WebApp.CloudStorage.setItem(
  "p_check0001",
  JSON.stringify({ id: "check0001-1", device: "check0001", clock: { check0001: 1 }, createdAt: new Date().toISOString(), format: 99, parts: 1, checksum: "00000000", resolves: [], reads: [3, 4, 5, 6] }),
);
// после проверки: Telegram.WebApp.CloudStorage.removeItem("p_check0001")
```
