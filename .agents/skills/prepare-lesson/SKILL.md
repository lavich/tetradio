# Подготовка занятия из материала пользователя

Полная инструкция: [`docs/lesson-authoring.md`](../../../docs/lesson-authoring.md). Шаблоны форматов:
[`docs/lesson-authoring/`](../../../docs/lesson-authoring/). Этот навык — короткий порядок действий и границы.

## Прежде чем начать

1. Прочитать `docs/lesson-authoring.md` целиком: там форматы, правила происхождения и правила повторной обработки.
2. Определить **режим поручения** по словам пользователя:
   - `extract` — по умолчанию: перенести присланное;
   - `transform` — названное преобразование имеющегося материала («разбей на фразы», «переведи эти фразы»);
   - `generate` — только по явной просьбе создать новый материал в заданных границах.
3. Найти целевой курс и урок. Если однозначного соответствия нет — уточнить до привязки, а не угадывать.

## Границы

- **Только присланное и запрошенное.** Предложения, темы, формы, правила, переводы, объяснения и альтернативные
  ответы не добавляются без просьбы.
- **Виды карточек — только слово и фраза.** Заданий с пропуском в приложении нет: просьбу их подготовить нужно
  отклонить, сказав об этом прямо, и предложить внести те же предложения фразами.
- **Не переключать режим.** Неразборчивый или неполный исходник не повод перейти в `generate`: неясное место
  идёт в отчёт списком, карточка с догаданным ответом не публикуется.
- **Не выдумывать цитаты.** У созданного по запросу материала `sourceLabel` называет автором агента,
  а `locator`/`excerpt` заполняются только при реальном опорном исходнике.
- **Не менять чужое.** Правка реальных уроков, слов и настроек — отдельная задача; проверочные примеры
  в основной каталог не публикуются.

## Материал

Текст, читаемые изображения и PDF разбираются своими средствами модели; внешний OCR не требуется и не подключается.
Если фрагмент не читается надёжно — он в списке неясного. В отчёте остаются точные ссылки на страницы, строки
или фрагменты; пользователь не размечает исходник в YAML сам.

## Порядок

1. Разобрать материал, выписать элементы, которые просили.
2. Проверить существующие ID: повторная присылка переиспользует карточки, правка сохраняет `id`.
3. Создать или обновить файлы: `content/words/`, `content/phrases/`, урок в `content/lessons/`
   (`items` для смешанного состава).
4. Заполнить `provenance` у каждой фразы; при отличающемся происхождении поля — `provenance.parts`.
   Примеры, которые агент готовит сам, размечать полем `words`: перевод каждого слова в контексте и ссылка
   на существующую карточку, если она есть (раздел «Разметка слов примера» в `docs/lesson-authoring.md`).
   Примеры преподавателя — только по просьбе. Новых карточек ради разметки не заводить.
5. Прогнать проверки проекта:

```bash
npm run content
npm run typecheck
npm test
```

6. Дать отчёт: режим, что добавлено, изменено, переиспользовано, что не разобрано, какие проверки выполнены.
   Отдельно указать, что готовы исходники, а не опубликованный урок: успешная сборка не доказывает языковую
   корректность и не означает, что урок появился в приложении.
