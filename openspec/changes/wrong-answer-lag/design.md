# Design

## Контекст

- `src/storage/courses.ts` `courseCardIds` — id карточек вида в уроках курса; читает связи всех уроков курса.
- `src/storage/queries.ts` `optionPool`/`phrasePool` берут из него 48 случайных id; `recordAnswer` (`src/storage/ops.ts`) зовёт их до транзакции записи через `easierRetry`, только для неверного ответа под заданием со ступенью проще (`assembly`, `spelling`, `comprehension`).
- `dexieSource.itemsOf` (сборка занятия, план) использует тот же запрос.
- Схема `lessonItems`: `[lessonId+unitKey],unitKey,[lessonId+position]`; своего индекса по `lessonId` нет.

Зонд, 99 уроков, 1244 связи (мс): `lessonItems.toArray` 2; `primaryKeys` 1; 99 диапазонов `[lessonId+unitKey]` 8; `where("lessonId").anyOf(99 id)` 1742–1760. `anyOf` по префиксу первичного ключа — один курсор с шагом на строку (по 10 урокам 116 мс): цена растёт с числом строк, а не уроков × таблицу.

## Goals / Non-Goals

**Goals:** неверный ответ на `assembly`/`spelling` — единицы миллисекунд на курсе; результат запросов тот же.

**Non-Goals:** кэш (нечего кэшировать: чтение дешёвое, кэш добавил бы сброс по `lessons`/`lessonItems`/`catalog`/`meta` и риск устаревших карточек); новый индекс (миграция базы); ответ в фоне.

## Решения

### Одно чтение таблицы вместо курсора `anyOf`

`lessonItemsOf(lessonIds, database)` в `courses.ts`: `database.lessonItems.toArray()` и отбор по `Set` id уроков. `toArray` идёт в порядке первичного ключа `[lessonId+unitKey]` — тот же порядок, что у `anyOf` (проверено на id вида `10.1`/`1.5`). Один запрос — один согласованный снимок: параллельные диапазоны могли бы увидеть установку урока наполовину. Диапазоны по уроку (8 мс) и кэш отвергнуты: диапазоны требуют транзакции для снимка и осторожности при вызове внутри чужой транзакции, а кэш — сброса по `lessons`/`lessonItems`/`catalog`/`meta`. Цена — чтение строк других курсов (две тысячи строк — единицы миллисекунд).

Порядок результата нужен `courseCardIds` (после `Set` идёт `sort()`) и тесту эквивалентности; `plan.ts` пересортировывает `itemsOf` сам.

Затронутые вызовы: `courseCardIds`, `dexieSource.itemsOf`. Остальные `where("lessonId")` — по `packages` и `blockProgress`, где `lessonId` — индекс; `lessonItems(lessonId)` читает один урок по `[lessonId+position]` и нужен порядок по позиции.

## Risks / Trade-offs

- Таблица со многими курсами читается целиком: линейно по числу связей на устройстве; если на устройстве лаг останется — кэш или ответ в фоне, решение пользователя.
- План (`itemsOf`, `phraseCount`) читает таблицу связей целиком и подписывает на неё живой запрос: запись связей другого курса перезапускает план; при малом числе уроков чтение тяжелее прежнего `anyOf`. Принято: перезапуск дешёвый; гибрид (диапазоны при малой выборке) — если замер покажет.
- Время в Node не равно времени на телефоне: замера на устройстве нет, он остаётся ручной проверкой после релиза.
