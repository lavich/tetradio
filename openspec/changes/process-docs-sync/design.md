# Design

## Context

См. proposal.md — Why. Копии `feature-flow` лежат в `.claude/skills/` и `.agents/skills/`; `prepare-lesson` — только в `.agents/skills/`. CI запускает команды в нескольких задачах (`ci.yml`): lint-задача, `test:unit`, `test:heavy`, `build` + `check:bundle`, шарды e2e, `e2e-course`/`e2e-courses`.

## Decisions

- **Тест вместо симлинка и вместо `verify`-скрипта.** Симлинк плохо переносится (Windows, архивы), а скрипт `verify` в `package.json` — ещё одна копия списка CI и зона конфликтов с соседними изменениями. Тест читает `ci.yml` и ловит расхождение при следующем изменении CI.
- **Сверка по именам команд.** Тест разбирает `ci.yml` пакетом `yaml` (уже в devDependencies), берёт `steps[].run`, раскрывает `${{ matrix.<ключ> }}` значениями `strategy.matrix` и выделяет имена `npm run <имя>` (до пробела). В разделе 4 навыка имя ищется как токен `npm run <имя>` целиком, а не как подстрока. Исключения: `check:flaky` (диагностика отчёта), `test:unit` и `test:heavy` (две части `npm test`, который навык оставляет одной командой).
- **`check:bundle` с окружением CI.** В CI окружение (`BASE_PATH=/tetradio/`, `SENTRY_DEBUG_IDS=1`, `VITE_TELEGRAM_MOCK=`, `VITE_TELEGRAM_BOT`, `VITE_SENTRY_DSN`) задано `npm run build`, а `check:bundle` получает только `BASE_PATH`. Навык повторяет это: одна сборка с окружением CI вместо `npm run build` без него, затем `check:bundle`. Собирать два варианта не нужно.
- **Курсы в e2e.** CI всегда гоняет `test:e2e:course` и `test:e2e:courses`; условие «если задеты два курса» из навыка убирается.
- **Задания в `prepare-lesson`.** Навык остаётся про слова, фразы и `items`; задания `blocks` — по формату курса. Границы режимов и «только присланное» не меняются.
- **`release`.** Пункт 1.6 остаётся `- [ ]` со ссылкой на issue и пометкой «вынесено»; архивация — `openspec archive release --yes` (неинтерактивно, с предупреждением о незакрытой задаче). Архивация создаёт `delivery` с Purpose-заглушкой, на которой `npm run spec` падает, поэтому Purpose вписывается сразу.
- **Спецификация только про постоянное.** Правило про архивацию изменений разовое и в основную спецификацию не идёт.

## Risks / Trade-offs

- [Тест привязан к тексту `ci.yml`] → разбор только строк `run: npm run …`; при смене формата CI тест падает громко.
- [Архивация `release` с вынесенным пунктом] → запись остаётся `[ ]` с «вынесено в #N», не «выполнено».
- [Purpose-заглушка после архивации] → задача 3.2 вписывает его; то же для `agent-process` при архивации этого изменения.
