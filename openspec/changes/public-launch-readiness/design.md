## 1. Данные пользователя

### Что где хранится

**Устройство (IndexedDB, Dexie).** База `tetradio-tg-<бот>-<Telegram ID>` (`src/storage/profile.ts`, `src/storage/db.ts:115`). Таблицы пользовательских данных — `TABLES` (`db.ts:123-141`): слова, фразы, уроки, курсы, `lessonItems`, `assets`, `media`, `packages`, состояния карточек FSRS (`cardStates`), события ответов, занятия, настройки, `meta`, `cardSkills`, `baseSummary`, `cardStash`, блоки уроков. В `blockProgress` лежат ответы по пунктам, отметки самопроверки и **текст письменного ответа** (`src/domain/types.ts:186-198`). Каталог и модули — кеш, не данные пользователя (`db.ts:122`). Вне базы: `localStorage` — переключатель тактильного отклика (`src/platform/haptics.ts:12-19`) и признак подсказки (`src/features/course/WordTaps.tsx:27`); `sessionStorage` — контекст запуска, включая `id`, имя, фамилию и username Telegram (`src/platform/launch.ts:104-113`), служебные метки перезагрузки и запуска (`launch.ts:171`, `:194`; `src/app/stale-build.ts:23`), позиции прокрутки (`src/app/scroll.ts:23`), только на время вкладки; в `localStorage` ещё служебные записи автообновления (`src/app/auto-update.ts:210`); полный перечень — `rg "(local|session)Storage" src`; отдельная база очереди Sentry `tetradio-error-reports` (`reporting.ts:42`); кеш service worker с уроками и аудио — не личные данные.

**Полная копия** (`exportFull`, `src/features/backup/backup.ts:30-40`): все таблицы `TABLES` без каталога, модулей и служебных ключей синхронизации. Файл содержит имя базы, то есть Telegram ID (экран показывает его пользователю: `BackupSection.tsx:143`). Файл уходит туда, куда пользователь его передал (`navigator.share` или скачивание).

**Telegram CloudStorage** (`src/sync/`): компактный снимок прогресса целой версией — пройденные уроки, блоки (`done`, счёт, отметки), состояния карточек FSRS, навыки, статистика за 14 дней (`docs/sync.md`, «Что входит в снимок»; `src/sync/types.ts:55-65`). Не входят история ответов, введённые ответы, текст письма, сессии. Ключи: указатель `p_<устройство>`, части `v_<версия>_<n>`, паузы курсов `cp_<устройство>` (`src/sync/adapter.ts:72-78`); метка платформы устройства (`ios`, `android`, …) лежит в указателе (`src/sync/index.ts:23`, `types.ts:81`). Свой сервер не участвует: область CloudStorage задаёт сам Telegram для пары «пользователь + бот» (не проверяемо по коду).

**Sentry** (`src/reporting/`). Только при заданном `VITE_SENTRY_DSN` (`reporting.ts:54`); для публичной сборки он задан переменной репозитория, адрес приёма — `ingest.us.sentry.io` (регион США; `gh variable list`, ключ в ответ не включён). Включено по умолчанию (`types.ts:273`), выключается переключателем «Отправлять отчёты об ошибках»: очередь удаляется сразу (`reporting.ts:135-155`). Событие: тип и стек ошибки, релиз `tetradio@<версия>+<сборка>`, метки `env`, `app.version`, `app.build`, `tg.version`, `tg.platform` (`reporting.ts:117-125`), поля, которые SDK и сервер Sentry добавляют сами (`contexts` браузера и ОС, `sdk`, `event_id`, серверное определение IP и региона по запросу) — `scrubEvent` их не трогает (`scrub.ts:79-98`), состав не проверяем по коду; дополнительные поля только из списка `category`, `kind`, `packageId`, `packageVersion`, `componentStack` (`scrub.ts:9`), адреса режутся до пути (`scrub.ts:17-27`), поле пользователя удаляется (`scrub.ts:84`), из крошек остаются навигация, запросы к собственному контенту и события сворачивания с размерами окна (`scrub.ts:36-60`), консоль и клики выключены у источника (`sentry.ts:29-36`). Исключение — отчёт о том, что не открылась база: настройка в этот момент недоступна, отчёт уходит всегда (`src/main.tsx:104-107`). Текст на экране — `REPORT_BOUNDARIES` (`BackupSection.tsx:16-17`).

**Хостинг и сторонние запросы.** Страницы, уроки и аудио отдаёт GitHub Pages: IP-адреса запросов видит GitHub (не проверяемо по коду). Приложение загружает `https://telegram.org/js/telegram-web-app.js` (`src/platform/bridge.ts:3`). DNS в Cloudflare без проксирования (`docs/telegram.md:7`), трафика Cloudflare не видит (не проверяемо по коду). Запросов к Google Cloud Text-to-Speech из приложения нет: синтез идёт при подготовке контента (`docs/voices.md`, `npm run voices`), остальное озвучивает синтез речи устройства. Метрик, рекламы, cookie и аналитики в коде нет; телефон, сообщения, контакты и платежи не запрашиваются (`docs/telegram.md:17`). Серверной проверки `initData` нет.

### Удаление данных

В приложении нет действия «удалить мои данные». Пользователь может: стереть данные клиента Telegram или браузерной оболочки (результат зависит от клиента), отключить отчёты, удалить отложенные версии облака. CloudStorage он сам очистить не может: интерфейса к нему нет, а ключи — служебные. Что происходит с CloudStorage при удалении чата с ботом или блокировке бота, по коду не определить и в документации проекта не описано — не проверяемо по коду; проверка на устройстве входит в задачу B3.

Другое устройство восстановит данные в облаке само: если указатель устройства пропал, оно публикует версию снова (`src/sync/coordinator.ts:388`). Поэтому удаление должно быть описано как действие на каждом устройстве.

**Минимальная форма.** Раздел «Удаление данных» в «Настройках и данных» под «Копией» с диалогом подтверждения по образцу замены копией (`BackupSection.tsx:148-179`):

1. Предложение сначала сохранить полную копию (существующая кнопка).
2. Остановить синхронизацию на этом устройстве.
3. Удалить из CloudStorage все ключи с префиксами `p_`, `v_`, `cp_` (новый метод адаптера; `transport.removeItems` уже режет вызовы по 64 ключа: `src/sync/transport.ts:154-156`). Отказ или нет сети — удаление не начинается, текст говорит об этом.
4. Закрыть соединения с базой (вкладка, блокировка синхронизации `webLock`), затем удалить базу Dexie, очередь Sentry и очистить `localStorage` и `sessionStorage` целиком (ключи служебные и разбросаны по модулям); перезапустить приложение — оно начнёт как у нового пользователя.
5. Текст диалога: действие надо повторить на других устройствах, иначе они опубликуют свою версию снова.

Не входит: удаление данных, которые пользователь передал сам (файлы копии), и отчётов, уже принятых Sentry (по ним нужен процесс через владельца проекта — вопрос владельцу).

### Политика конфиденциальности

Адрес `https://tetradio.app/privacy`: статическая третья страница сборки (в `vite.config.ts:122-127` два входа — `index.html` и `app/index.html`; добавляется третий) со ссылкой из подвала лендинга (`src/landing/render.ts:144`) и из «Настроек». Лендинг при этом остаётся без базы и без хранения. Содержание — по фактам выше:

- кто отвечает и как с ним связаться (решение пользователя: имя или псевдоним, адрес);
- что хранится на устройстве, что уходит в CloudStorage, что в Sentry (перечень полей, регион, переключатель, исключение для отказа базы), что видят GitHub и Telegram;
- чего нет: аналитики, рекламы, cookie, регистрации, номера телефона, сообщений, контактов, платежей;
- как удалить данные (после задачи B3) и как попросить удалить отчёты;
- срок хранения отчётов Sentry — настройка проекта, не проверяемо по коду;
- возраст, юрисдикция, основания обработки — вопросы владельцу (раздел «Вопросы владельцу»).

Тон — PRODUCT.md: короткие факты без оценочных слов.

## 2. Бот и первый контакт

Приложение открывается как Main Mini App бота (`docs/telegram.md:13`, настройка в BotFather по `Configure Mini App`) и по ссылкам `https://t.me/TetradioBot?startapp[=w_<id>|c_<id>]` (`src/platform/launch.ts:158-165`, `src/platform/share.ts:9-11`). Серверной части у бота нет, `/start` и сообщения никто не обрабатывает (`docs/telegram.md:17`). Человек, написавший боту, не получает ответа; чат показывает то, что задано в BotFather. Текущие значения описания, about, команд, кнопки меню и аватара — не проверяемо по коду: проверить пользователю в BotFather и на устройстве (проверки «Запуск из профиля бота и по `?startapp`» в `docs/telegram.md:106` — «не проверено»).

Варианты:

| Вариант | Что даёт | Стоимость и поддержка |
| --- | --- | --- |
| A. Только BotFather | Description, About (с контактом), кнопка меню Mini App, аватар; команд без обработчика не задавать — они обещают ответ, которого нет | 0 ₽, 0,5 часа пользователя; поддержки нет. Сообщение боту остаётся без ответа, об этом говорит текст Description |
| B. Серверлесс-вебхук (например, Cloudflare Worker: домен уже в Cloudflare) | Ответ на `/start` и на любое сообщение: два предложения и кнопка «Открыть» (`web_app`), ссылка на контакт | Бесплатного тарифа Cloudflare Workers для такого трафика, по их документации, хватает (проверить актуальные лимиты). Появляется секрет — токен бота (сейчас он нигде, кроме BotFather, не хранится: `docs/telegram.md:3`), его ротация, мониторинг, обработка ошибок; ~1–1,5 дня. Решает владелец |
| C. Бот поддержки отдельно | Отдельный бот или чат для вопросов; основной бот остаётся без сервера | Нужен человек, который отвечает; без сервера — ручная переписка |

Рекомендация: A до запуска; B — после запуска, если сообщения боту окажутся реальным каналом (решение пользователя; без метрик это можно заметить только по прямым обращениям).

Путь по коду для человека без прогресса и без греческого:

- **Вне Telegram.** Адрес `app/` в браузере уводит на лендинг (`src/main.tsx:86-87`), лендинг — полка 24 модулей, пробный урок и кнопка на бота (`src/landing/render.ts:35`, `:144`).
- **В Telegram без пользователя.** «Не удалось определить аккаунт» без прогресса и без отправки (`src/app/LaunchGate.tsx:6-20`).
- **Первый запуск.** «Сегодня» без установленных уроков показывает «Выберите курс», строку «Курсы языков с уроками по программе и ежедневным повторением карточек» и карточки каталога (`src/features/today/TodayScreen.tsx:39-49`). Карточка: название, цель, объём, «Учить курс» (`src/features/today/FirstRun.tsx:150-176`). Карточка уже называет уровень и объём («Греческий · A0 → A2», цель «С нуля до экзамена ΚΕΓ A2…», «24 модуля»: `course-offers.ts:20-27`, `:44-50`). Онбординга и пояснений о нагрузке в неделю и о нужном греческом голосе нет; нагрузка («2–3 занятия по часу в неделю») названа только на лендинге. После `hide-non-greek-courses` экран покажет одну карточку под заголовком «Выберите курс» и текстом про «курсы языков» — подпись остаётся в множественном числе; текст надо править вместе с этим изменением (порядок — первой строкой tasks.md).

## 4. Обратная связь и метрики

## Что решает только пользователь

- Кто назван оператором и какой контакт публикуется (имя, псевдоним, адрес, личный чат или бот поддержки).
- Политика конфиденциальности: текст и язык (русский; нужна ли английская копия), адрес, срок хранения отчётов.
- Нужен ли экран удаления данных до запуска (рекомендация — да: без него политика не может описать, как человек удаляет данные из CloudStorage).
- Отчёты об ошибках: включены ли по умолчанию (сейчас — да, `types.ts:273`) и нужно ли согласие при первом запуске.
- Метрики: вариант a, c или d (область 4).
- Поддержка: канал и кто отвечает; срок ответа, который обещается людям.
- Бот: только BotFather или серверлесс-вебхук (область 2).
- Аудитория и тон первого экрана: для кого написано «Выберите курс», упоминать ли экзамен ΚΕΓ и Кипр, указывать ли уровень входа.
- Открывать ли репозиторий и под какой лицензией (сейчас публичный, без лицензии).

## Вопросы владельцу для юридической сверки

Список вопросов без юридических выводов:

1. Условия Google Cloud Text-to-Speech (включая Chirp 3 HD): разрешают ли они распространять полученные аудиофайлы в составе публичного приложения и хранить их в публичном репозитории; нужна ли атрибуция.

3. Лицензия Microsoft Fluent Emoji (MIT): достаточно ли однострочной подписи в приложении или текст лицензии должен поставляться вместе с картинками в сборке.
4. Лицензия шрифтов Literata и Manrope (OFL): состав файла `NOTICE`.

6. Лицензии `npm`-зависимостей, включая `shadcn` и `@base-ui/react`.
7. Условия Telegram для разработчиков ботов и Mini App: обязательность политики конфиденциальности, порядок её указания, требования к приложению в каталоге.
8. Политика конфиденциальности: возраст пользователей, юрисдикция (пользователи на Кипре и в других странах), основания для отчётов Sentry (по умолчанию включены), передача данных в регион США (`ingest.us.sentry.io`), срок хранения у Sentry, порядок запроса на удаление отчётов.
9. Ограничения GitHub Pages: допустимость использования для приложения, которое раздаётся неопределённому кругу людей, и лимиты трафика.

11. Образовательные заявления: допустимо ли говорить «подготовка к экзамену ΚΕΓ A2» при том, что курс не аффилирован с ΚΕΓ и проверен моделями, а не носителем.
