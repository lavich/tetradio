# Design

## Решения

**Черновики.** Статус урока берётся из `buildCourses(sources).moduleOf` (`draft`, `content/build/courses.ts:80`) — то же поле, по которому сборка не публикует записи. Без аргументов цикл реплик и группа `answers` пропускают такие уроки. Для ответов `planAnswerVoices` получает признак `held` из `context`: файлы удерживаемого урока не попадают в `stale`, как уже сделано для языка без карты голосов (`skipped`). Явный аргумент урока озвучивает его всегда (автор готовит запись до публикации); группа `answers` урока не принимает, поэтому ответы черновика озвучить можно только сняв статус — как сейчас.

**Очистка.** Чистая `staleRecords(planned, manifest, existing, owns)` в `content/build/voices.ts` возвращает отсортированные файлы из диска и манифеста, которые `owns` относит к области и которых нет в `planned`. Её используют реплики, слова и фразы; `planReadingVoices` и `planAnswerVoices` остаются как есть. Область реплик — файл вида `<папка>/<имя>-<n>.mp3` на один уровень, где папка не `words`, `phrases`, `readings`, `answers`. `planned` реплик — файлы всех реплик всех уроков (включая черновики) плюс значения `audio:`, прописанные в репликах и карточках вручную. Запуск с аргументами: реплики чистятся только в папках названных уроков, слова и фразы — если названы `words`/`phrases`; без аргументов — всё. Удаление и пустые папки — одна общая функция вместо копии в `voiceGroup`.

**Порядок и удалённые уроки.** Очистка идёт до синтеза: ошибка «нет голоса» опубликованного урока (`:145`) её не отменяет. Папка удалённого урока чистится только запуском без аргументов — явный id отсутствующего урока скрипт отвергает; `docs/voices.md` советует проверить `--check`. Урок вне модулей (нет в `moduleOf`) не черновик и озвучивается. Файлы урока черновика из очистки исключены, как `held` у ответов: черновик может вернуться в работу. `planned` собирается только из имён файлов (`lineFile`), без карт голосов, и не падает на языке без карты.

**Повторы.** `retrying(send, sleep)` в `content/build/voices.ts`: до 5 попыток; повтор при сетевой ошибке, 429 и ≥500; пауза `Retry-After` (число секунд, не больше 30; дата HTTP игнорируется), иначе 1, 2, 4, 8 с; тело ответа читается текстом и разбирается с `try/catch`, чтобы HTML от 502 давал ошибку с кодом, а не `SyntaxError`; последний ответ возвращается как есть и разбирается прежним кодом. `sleep` передаётся параметром — тест не ждёт. Запросы остаются последовательными: манифест пишется после каждой записи, параллель потребовала бы очереди записи и дала бы квоту 429 чаще.

**Ключ.** Заголовок `x-goog-api-key` уже есть (`:72`). Сообщение `error.message` сервиса проходит через `redactKey`. В `package.json` скрипт `voices` — `node --env-file-if-exists=.env scripts/voice-dialogues.ts` (`engines` — Node ≥ 22.18, флаг есть с 22.9); `GOOGLE_TTS_KEY` из окружения по-прежнему имеет приоритет над `.env`. `.env` в `.gitignore` уже есть. Без `.env` Node печатает «not found. Continuing without it» — docs это называют. Отбор уроков для синтеза (черновики, явные аргументы) — чистая функция в `voices.ts`, тестируется без ключа.

**Имя урока.** Сообщение называет `join(ROOT, "lessons")`.

## Риски

- Очистка удаляет файлы. Защита: `planned` включает черновики и ручные `audio:`, область ограничена шаблоном имени реплики, `--check` ничего не удаляет; файлы под git — удаление обратимо.
- Пропуск черновиков меняет вывод счётчика «Записей N» (меньше) — только текст отчёта.
