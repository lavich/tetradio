# Design

Статус: архитектурное направление и план аудита. Детальный контракт аккаунта/синхронизации уточняется до соответствующей реализации. Документы не означают, что код уже перенесён.

## Context

Источник: `/Users/lavich/Projects/lexi` (Tavelori), зафиксированная ревизия `2ccae7d3094351f8612e8f3c4b6ec3f1588ff8d6`; прежний осмотр — `218f3a0`, отличие только в UI экрана «Сегодня». На этой ревизии 657 unit-тестов пройдены, `npm run build` успешен. Результаты, карта файлов и пробелы — [docs/audit/tavelori-audit.md](../../../docs/audit/tavelori-audit.md).

Стек: React/TypeScript/Vite, Dexie, ts-fsrs, Vitest/Playwright, YAML-контент, PWA. Реальный sync-транспорт — Telegram CloudStorage, в обычном браузере — disabledTransport.

## Goals / Non-Goals

**Goals:** самостоятельный Telegram Mini App на существующей основе, полноценный курс, аккаунт и межустройственная синхронизация, сохранение полезных свойств движка.

**Non-Goals:** Supabase, собственный backend аккаунтов, отдельная веб-авторизация и самостоятельная браузерная версия; переписывание карточек и FSRS с нуля, изменение исходного Tavelori, перенос production-секретов и пользовательских данных, общий backend двух приложений без отдельного решения.

## Decisions

1. Сначала аудит, затем перенос выбранной основы в отдельный проект. Возможны копирование подходящих модулей или отделение приложения от фиксированной ревизии. Границу выбрать по зависимостям; выделение общей библиотеки для двух продуктов пока добавляет лишнюю связанность.
2. Сохранить React/TypeScript/Vite и учебный движок, где аудит подтверждает применимость. Не заменять FSRS фиксированными интервалами. Сохранить различие слова и фразы, историю повторений и существующую оценку упражнений.
3. Расширять существующие YAML-источники, сборщик контента, каталог и пакеты. Не вводить параллельный JSON-формат авторинга без необходимости. JSON может оставаться форматом собранных пакетов.
4. Основной маршрут нового приложения — «курс → модуль → урок → объяснение → практика → проверка». Карточки и повторение поддерживают урок, но не заменяют его. Текущие типы Course/Lesson требуют проверки перед расширением.
5. Платформа — Telegram Mini App; аккаунт берётся из Telegram-контекста без отдельной регистрации. Переиспользовать `src/platform/` и `src/sync/` с Telegram CloudStorage. Вне Telegram production-страница предлагает запуск через бота и не открывает локальные данные пользователя. Мок Telegram допускается только в явно включённом режиме разработки.
6. Dexie сохраняет локальный прогресс; Telegram CloudStorage переносит компактное состояние между устройствами одного аккаунта нового бота. Полный контент и медиа распространяются пакетами через статический хостинг, а не через CloudStorage. Кэширование оценивается в реальных клиентах Telegram; установка PWA не является продуктовым требованием. Нельзя одновременно обещать локальное сохранение и скрывать отсутствие облачного подтверждения. UI различает локально сохранённое, ожидающее синхронизации и синхронизированное состояние.
7. Один готовый модуль — проверка новой структуры до массового наполнения. Целевой результат включает весь курс; незаполненные модули не удовлетворяют приёмке.

## Content contract (schema 4)

Реализовано в 3.2 — [docs/course/format.md](../../../docs/course/format.md). Каталог получает `modules` (все 24, включая черновики) и `moduleIds` курса; пакет урока — `module {id, position}`, `lesson.kind` (`lesson` | `test`) и упорядоченные `blocks`: объяснение, лексика, задание (`choice`/`text`/`gap`/`match` с ключом и пояснением), чтение, аудирование (медиа + транскрипт + число прослушиваний), письмо (регистр, объём, образец, критерии), речь (часть экзамена, время, критерии). У слова — `forms`. Одна модель и проверки (`src/content/course.ts`) выполняются сборщиком и клиентом. Черновик виден в каталоге, но его уроки и медиа не поставляются; неполный модуль сборка публиковать отказывает. Клиент читает схемы 2–4; хранение блоков и прогресса по ним — задачи 3.3 и 4.2.

## Reuse map

| Часть Tavelori | Проверенная точка входа | Намерение |
|---|---|---|
| FSRS, навыки, проверка ответов | src/domain/ | Перенести с релевантными тестами |
| Учебные сессии и карточки | src/features/learning/, src/features/words/ | Адаптировать к уроку полного курса |
| Каталог, уроки, сборка | src/content/, content/build.ts, content/lessons/ | Расширить структуру и валидацию |
| Локальное хранение | src/storage/ | Проверить миграции, изоляцию аккаунтов и отдельное имя БД |
| Синхронизация | src/sync/, src/platform/ | Оценить переиспользование протокола; Перенести Telegram-транспорт; расширить снимок и проверить ограничения |
| Медиа, офлайн и копия | src/shared/, src/features/backup/ | Сохранить пригодное, проверить права и границы данных |
| Полный курс и контрольные | docs/curriculum.md в новом проекте | Создать содержание и недостающие типы уроков |

Это карта кандидатов, не утверждение о готовой совместимости. Конкретные файлы переноса фиксируются после аудита.

## Risks / Trade-offs

- Связанность с прежним ботом, брендингом и расписанием исходного продукта → карта зависимостей и самостоятельная конфигурация.
- Потеря FSRS-истории при новой модели курса → стабильные ID и регрессионные тесты.
- Утечка локальных данных между аккаунтами → разграничение владельцев и тесты смены аккаунта до подключения sync.
- Гонки и офлайн-действия → явный контракт доставки, дедупликации и конфликтов; проверка двух устройств.
- Копирование deployment-настроек старого приложения → отдельные бот, адрес Mini App, идентификаторы хранилищ и отключённые старые каналы публикации.
- Ошибки контента → проверка языка, ответов, аудио и покрытия четырёх навыков каждого модуля.

## Migration Plan

Зафиксировать исходную ревизию и карту переноса; проверить релевантные тесты источника; перенести код с тестами в целевой проект, сохранив его OpenSpec-документы. Не копировать .env, runtime-данные и production-привязки. Запустить основу с отдельной конфигурацией. Затем расширить модель курса, проверить пилот, адаптировать Telegram-контекст и CloudStorage sync, наполнить остальные модули и провести сквозную приёмку. Миграция личного прогресса из Tavelori — отдельная возможность, не автоматическое действие.

## Decisions after audit

1. **Граница переноса.** Копируем выбранные модули из ревизии `2ccae7d` в этот репозиторий по карте аудита. Общей библиотеки и подмодуля нет, история Tavelori не переносится. Легаси-миграции Dexie (v1–7), формат снимка 1, импорт и контент класса не переносятся.
2. **Локальные данные.** Новая БД Dexie начинается с версии 1. Имя — `<app>-tg-<bot>-<telegramUserId>`, префикс выбирается вместе с названием. Анонимного профиля и браузерного профиля в production нет. Без `user` в initData запуск останавливается с ошибкой; вне Telegram показывается предложение открыть бота. Режим разработки с моком Telegram включается только явным флагом сборки dev и использует отдельный префикс БД.
3. **Формат снимка.** Облако нового бота пустое, поэтому совместимость с форматами Tavelori не нужна. Поле `format` и механизм «неизвестная версия не применяется и не перезаписывается» сохраняются. Новые поля — компактно, массивами:
   - по уроку: ревизия контента, завершённые блоки, дата завершения;
   - по заданию навыка: попытки, последняя дата, самооценка;
   - по контрольной: попытка, балл, дата.

   Контент, тексты ответов и медиа в снимок не входят.
4. **Дедупликация.** Сохраняется модель Tavelori: снимок = база последней применённой версии + локальные события после её отсечки. Публикация версии идемпотентна — те же ключи частей и указателя. События уроков и заданий получают стабильные ID и учитываются так же, как ответы на карточки.
5. **Конфликты.** Сохраняется политика Tavelori: при расходящихся векторных часах пользователь выбирает одну версию целиком. Отвергнутые ветви хранятся локально до явного удаления, автоматического слияния нет. Для одного пользователя с 2–3 устройствами этого достаточно. Слияние по полям — отдельное решение, если конфликты начнут мешать.
6. **Вместимость.** Бюджет — не более 2 500 карточек (слова + фразы) на весь курс. CI-тест размера снимка с резервом `3 × части + 2` ключа должен укладываться в 1 024. При превышении публикация не начинается, очередь остаётся локальной, UI показывает проблему синхронизации (поведение `SyncError("limit")` сохраняется).
7. **Резервная копия.** Формат dexie-export с новым маркером приложения. Добавить проверку: восстановление отменяется, если после предпросмотра в облаке появилась более новая версия.
