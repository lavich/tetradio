# Proposal

## Why

После неверного ответа в заданиях «сборка» и «написание» кнопка «Сохраняем…» висит секундами (у пользователя на телефоне около 5 с). Замер на настоящем курсе `greek-a2` (99 уроков, 1244 связи `lessonItems`), Node + fake-indexeddb: неверный ответ на `assembly`/`spelling` — ≈1770 мс, из них `courseCardIds` ≈1760 мс; на `recognition`/`listening` и на любой верный ответ — 1 мс.

Причина (зонд 18.10.2026, подтверждён ревью плана): `courseCardIds` и `dexieSource.itemsOf` читают связи через `lessonItems.where("lessonId").anyOf(ids)`. `lessonId` — префикс составного первичного ключа `[lessonId+unitKey]`, поэтому Dexie выполняет `anyOf` одним курсором, по шагу на строку; в fake-indexeddb шаг ≈1,4 мс (1244 строки ≈1760 мс). Чтение пакетом (`getAll`: `toArray` всей таблицы — 2 мс, диапазоны — 8 мс) того же объёма строк на два порядка дешевле. Время на телефоне в Node не воспроизводится: замера на устройстве нет.

Решения пользователя: по этой задаче вопросов к пользователю нет — поведение для учащегося не меняется. Предпочтение пользователя (кэш id или выборка без полного чтения) не выбрано: по замеру в Node хватает смены способа чтения, а кэш добавляет риск устаревших карточек. Если на устройстве лаг останется, следующий шаг — кэш или ответ в фоне, решение пользователя.

## What Changes

Требование пользователя — убрать задержку без изменения поведения для учащегося. Предлагаемый объём:

- Общая функция чтения связей уроков одним `toArray()` таблицы с отбором по набору уроков в памяти (один снимок, без параллельных транзакций); порядок результата прежний (по `lessonId`, затем `unitKey`).
- `courseCardIds` и `dexieSource.itemsOf` читают связи через неё.
- Тест на настоящем курсе: неверный ответ на `assembly`/`spelling` слова и фразы укладывается в предел, пул вариантов корректен; результат совпадает с прежним `anyOf`; курс не отдаёт карточки другого курса.

Не входит: кэш в памяти, ответ в фоне (предложить пользователю, только если после правки останется заметная задержка на устройстве), правки схемы Dexie (новый индекс потребовал бы миграции базы); другие `anyOf` по `unitKey`/`id` (`courseOfCards`, `lessonMates`, `phraseCount`) — читают десятки строк, не затронуты.
