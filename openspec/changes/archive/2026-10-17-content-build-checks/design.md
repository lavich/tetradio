## Context

См. proposal.md. Сборка `npm run content` — 1,6 с на `main` a4deb24. Исходники читает `readSources` (`content/build/sources.ts`): `load` вызывает `yaml.parse` без обработки ошибок, поля не проверяются, `lessons` — `Map` по имени без расширения. Соседнее изменение #158 правит `content/build/voices.ts` и `answers.ts` — они здесь не меняются; проверка допустимых полей голосов уже есть в `voices.ts`, тексты для чтения — в `readings.ts` (`FIELDS`).

## Goals / Non-Goals

**Goals:**

- Каждая ошибка исходников называет файл; опечатка в поле — ошибка сборки.
- Картинки библиотеки не слабее собственных; источник картинок закреплён.
- Сборка проверяет пакеты и каталог форматом клиента всегда и не меняет исходники.
- Один набор греческих артиклей для `marks.ts` и `coverage.ts`.

**Non-Goals:**

- Окончания слов, `inflected` в `questions.ts`, `GRAMMAR` в `coverage.ts` (решение пользователя 17.10.2026: «Только артикли, без смены поведения»).
- Правка `voices.ts`, `answers.ts`, форматов пакета и каталога, приложения.
- Списки артиклей в `scripts/check-lexicon.ts` (там только 5 форм именительного: регулярка `^(ο|η|το|οι|τα) ` задаёт «существительное без артикля»), `src/domain/phonetics.ts`, `src/domain/syllables.ts` — у них другая задача, слияние изменило бы поведение.
- Проверка палитры и `viewBox` для картинок библиотеки: у них свой формат и лимит 12 КБ.

## Decisions

1. **Разбор YAML — один помощник `parseYaml(text, where)` в `common.ts`.** Ловит ошибку `yaml`, бросает `ContentError("<where>: <первая строка сообщения>")` (в ней строка и столбец). Документ должен быть картой, иначе «ожидалась карта полей». Используется в `load`, для `pictures.yaml` и для `voices/*.yaml` (текст разбирается им до `parseVoices`, который в зоне #158 не правится). Альтернатива — ловить в `buildContent` целиком: теряется, какой файл.
2. **Допустимые поля — таблицы `satisfies Record<keyof XSource, true>`.** Компилятор не даст разойтись интерфейсу и списку. Проверка — отдельный шаг `checkSources(sources)` в `buildContent` сразу после `readSources`, а не внутри `readSources`: `scripts/voice-dialogues.ts` (ветка #158) тоже вызывает `readSources` и намеренно терпит урок с непонятной структурой. `readSources` отвечает только за разбор файлов (пункт 1 и двойные файлы); для этого `Sourced` хранит документ как есть. Шаг проверяет: лишнее поле → ошибка; поля-списки (`grammar`, `lessons`, `review`, `examples`, `reading`, `items`, `words`, `blocks`, `modules` — каждое в своём типе) — `Array.isArray`; элементы `examples`, `reading`, `items` — объекты (`examples: [null]` не даёт `TypeError`); `examples[].words` и `paradigm` уже проверяют `glossesOf` и `paradigmOf`. Для урока `status` и `targetDate` остаются с прежним пояснением через `hints`. `file` и `course` добавляются после загрузки и в проверку не попадают. Тексты для чтения — прежний `FIELDS` в `readings.ts`, голоса — `voices.ts`.
3. **Двойной файл урока.** `lessons` в `readSources` собирается циклом с проверкой, как `byId` (двойной файл — ошибка и для скрипта озвучки: подмена молчком опаснее): `lessons/<a>.yml` и `lessons/<a>.yaml` → ошибка с обоими путями. Курсы и модули уже ловит `idOf` по id, карточки — по id.
4. **Общие запреты SVG.** `FORBIDDEN` из `art.ts` выносится как `forbiddenIn(svg)`, возвращающая голую причину; суффикс «запрещено стандартом иллюстраций» остаётся в `checkArt`. `mediaFor` (папка `pictures`) вызывает её, остальные правила `media.ts` (только SVG, 12 КБ) остаются. Данные: 150 картинок библиотеки проходят набор без замечаний — пересчитывается в задаче 3.1.
5. **Закрепление источника картинок.** В `scripts/pictures-sync.ts` зеркала `@main` и `/main/` заменяются SHA `1ffb34c752ecf5d402f04cfb4b392c77f57c54bc` (HEAD `microsoft/fluentui-emoji` на 17.10.2026) в одной константе. Уже скачанные файлы не перекачиваются: правка влияет только на новые.
6. **Пакеты и каталог — всегда.** Замер на `main`: `parsePackage` на всех 103 пакетах и `parseCatalog` на каталоге ошибок не дают, 36 мс — все пакеты сегодня уже проходят условие `marks`/озвучка/тексты; изменение — гарантия для будущих пакетов, а не исправление текущего. `output.ts`: `parsePackage` на каждый пакет (прежняя сверка `voicedOf` — только когда есть тексты для чтения); `buildContent` вызывает `parseCatalog` на каталоге, копия не нужна. Цена измеряется в 4.1: допустимо до +0,3 с.
7. **Сообщения.** (а) `readings.ts`: если урок входит в модуль-черновик (`moduleOf.get(after)?.draft`), — «урок X в черновом модуле — тексты открываются после опубликованного урока». (б) Спорные места: проверка показала, что это не дубли источника — 10 мест одного слова «κρύο» (две карточки) в 7 уроках, три из них в одном поле; отчёт сводит места одного «слово → карточки» в одну строку со списком уроков и блоков, счётчик «спорных мест N» считает места. (в) Переброс `ContentError` (`lessons.ts`, `courses.ts`) — `throw error` как есть: новый экземпляр с тем же текстом ничего не добавляет.
8. **Сборка не меняет исходники.** `checkCardAudio` не пишет в источник: возвращает `{ voicing, sources }`, где `sources` — копия `ContentRoot` с копиями записей `words` и `phrases` (`{...src}`), у устаревших без `audio`. Копию получают `buildCards` и `buildMedia` — только они читают `src.audio` карточек (`cards.ts`, `media.ts`); остальные шаги берут `sources` целиком. `BuiltContent.sources` — исходный, неизменённый `ContentRoot` (единственный потребитель, `tests/content-mixed.test.ts`, читает `lessons`). `scripts/voice-dialogues.ts` читает `src.audio` из своего `readSources` и не затронут.
9. **Артикли.** `content/greek.ts` (новый) — массив `ARTICLE_WORDS` (сырой: `norm` живёт в `marks.ts`, нормализация в потребителях — без цикла импортов). `marks.ts` строит из него `ARTICLES`, `coverage.ts` — начало `GRAMMAR`, остальные слова `GRAMMAR` не меняются. Состав слов не меняется: в тесте оба набора равны прежним литералам.

## Risks / Trade-offs

- Строгие поля могут отклонить поле, которое автор вставит «на будущее»: это и есть цель; сообщение называет файл и поле.
- `parsePackage` на всех пакетах удлинит сборку; предел +0,3 с, иначе — отдельное решение.
- `forbiddenIn` строже нужного библиотеке (`<title>`, `<desc>`, `<style>`, `<text>`, `<animate>`): новая иконка Fluent с `<title>` будет отклонена — осознанно, как у своих иллюстраций; сегодня 150 из 150 проходят.
- Закрепление по SHA требует ручного обновления при пополнении библиотеки — одна строка комментария рядом с константой.
- Слияние артиклей не должно менять `public/content`: проверяется побайтовым сравнением до/после (задача 5.1).

## Реализация

- Двойные файлы урока ловит `readSources`, остальные проверки формы — `checkSources` в `buildContent`: озвучка (#158) читает `readSources` и терпит урок с непонятной структурой.
- Спорные места — сводка по слову (см. 7б); текстов отчёта до/после различается только этот блок, `public/content` совпадает побайтово (4894 файла и каталог без `generatedAt`).
- Сообщение про урок чернового модуля идёт через `moduleOf.get(after)?.draft`; `ContentError` из `parseModule`/`parseBlocks` больше не пересоздаётся — сохраняется исходный `kind`.
- Сборка 1,64 с (было 1,6): `parsePackage` на всех пакетах и `parseCatalog` стоят в пределах шума.
- Зеркала с закреплённым SHA отвечают 200; `node scripts/pictures-sync.ts` оставляет `content/pictures` и `pictures.yaml` без изменений.
