# Proposal

## Why

Скрипт озвучки (`scripts/voice-dialogues.ts`) тратит платные символы Google TTS впустую и оставляет мусор (GitHub issue #158):

- Запуск без аргументов озвучивает реплики аудирования (`:125`) и ответы заданий (`:225`) уроков черновых модулей, а сборка эти записи не публикует: для черновика `shipped = false` (`content/build/lessons.ts:83`). Сейчас в черновых модулях e02–e16 нет файлов уроков, поэтому убыток пока нулевой; первый же черновой урок получит платные записи без пользы.
- Очистка устаревших файлов есть только у текстов для чтения и ответов (`:197-208`). Файлы удалённых реплик и карточек остаются на диске и в манифесте.
- Запрос к API один, без повторов: единичный 429 или 5xx обрывает многочасовой запуск (`:72`).
- Проверка имени урока говорит «content/lessons» и при `CONTENT_ROOT` (фикстура e2e) вводит в заблуждение (`:34`).
- Совет в `docs/voices.md` запускать с `GOOGLE_TTS_KEY=…` оставляет ключ в истории оболочки.

## What Changes

Требование пользователя (issue #158, 17.10.2026): пять пунктов выше исправить; решений, меняющих поведение для учащегося, нет.

Предлагаемый объём (решения по реализации, пользователь их не формулировал):

- Запуск без аргументов пропускает уроки модулей со статусом `draft` для реплик и ответов; файлы черновиков не удаляются. Урок, названный явно (`npm run voices -- e02-1`), озвучивается как раньше.
- Очистка лишних файлов реплик (`<урок>/<блок>-<n>.mp3`) и карточек (`words/`, `phrases/`): файл и запись манифеста без реплики или карточки в исходниках удаляются; при запуске только с некоторыми аргументами — только в их области. `--check` называет такие файлы, но не удаляет.
- Повтор запроса при 429, 5xx и сетевой ошибке: до 5 попыток, паузы 1, 2, 4, 8 с (или `Retry-After`).
- Сообщение об ошибке имени называет настоящий каталог `<CONTENT_ROOT>/lessons`.
- Ключ: уже уходит заголовком; текст ошибки очищается от ключа; `npm run voices` читает локальный `.env` сам (`--env-file-if-exists`), в `docs/voices.md` команды без `GOOGLE_TTS_KEY=…`.

Вне объёма: параллельные запросы (манифест пишется после каждой записи, очередь последовательна намеренно), озвучка слов и фраз по статусу модуля (карточки принадлежат курсу, а не модулю), формат манифеста и пакетов, облако и база.
