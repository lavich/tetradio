# Tasks

Зависимость: архивация по цепочке `drop-lesson-mistakes` → `progress-weeks` → `sync-review-days` (требование «Страница «Прогресс»» — полным текстом поверх `progress-weeks`); также после `sync-compression` (формат 6) и `delete-data` (удаление данных), на которые ссылается новое требование.

## 1. Домен и кодек

- [x] 1.1 Функция домена «день планового повторения» (по `event.localDate`, без `practice`, `isPlanned`) и сложение событий в `reviewDays` по курсам; `history` переходит на неё. Проверка: unit — тренировка урока не даёт дня, день — `localDate` события, событие без курса не учитывается, результат отсортирован без повторов; критерий вне плана — общий `isPlanned` (design, «Реализация»).
- [x] 1.2 Поле `reviewDays` в `CompactSnapshot` и `BaseSummaryRow`; `rd` в кодеке (номера дней с разностями). Проверка: unit — круговое кодирование, пустые дни не пишутся; отсутствующее `rd`, не массив, отрицательный первый номер, нецелое число, нулевая разность, день после 2100 года — курс отброшен без ошибки, остальные курсы и снимок применяются; день со сбитых часов (1969, 2026-02-30, 2101) не пишется; версия формата 5 и 6 с `rd` читается. Совместимость — по замороженной фикстуре: проводной снимок с `rd` в `tests/fixtures/` декодируется копией `decodeSnapshot` из `main` без ошибки (`loadBuild` подменяет только константы и для этого не годится).

## 2. Снимок

- [x] 2.1 Сбор при публикации: свежие события по правилу design («Свежие события для дней»), дни собираются целиком в транзакции чтения прогресса и передаются в транзакцию записи готовыми. Проверка: unit — первая публикация при базе без поля содержит дни всей истории; новое событие добавляет день; событие с `createdAt` раньше `asOf` после перевода часов назад даёт день; ответ, записанный между транзакциями чтения и записи, попадает в следующую публикацию запасом в сутки (design, «Реализация»).
- [x] 2.2 Применение версии: без исключения `events` и с таблицами `cardCourses` в транзакции; объединение прежних дней базы, свежих событий по тому же правилу и дней версии; дни других ветвей конфликта — параметром `reviewDays` (design, «Реализация»). Проверка: unit — база без поля + `applySnapshot(ifClean)` + публикация → версия содержит дни всей истории устройства; «Объединение двух устройств»; «Устройство на прежней версии» — версия без `rd` и база без поля (как пишет прежний `commitBase`) не стирают дней.
- [x] 2.3 Конфликт: при выборе версии другого устройства (и в конфликте `restored`) публикуется `{ ...chosen.snapshot, reviewDays: объединённые }`; при выборе «Это устройство» дни отвергнутых ветвей дописываются в базу в `resolveNow` до `publish(null)`. Проверка: unit координатора — содержимое **опубликованной** версии в обоих выборах конфликта `diverged` содержит дни обеих ветвей; `restored` идёт той же веткой `resolveNow`.

## 3. Показ

Точки у строки урока на «Сегодня» не меняются. Проверка: unit `progress` — день только из облака виден в сетке курса, в сумме языка и в «повторение N дней» недели, день другого курса — нет, испорченное поле базы — без дней и без ошибки; перенос — unit-тестом координатора с двумя базами и общим облаком вместо e2e (design, «Реализация»).
