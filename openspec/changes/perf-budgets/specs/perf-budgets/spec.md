## ADDED Requirements

### Requirement: Бюджет сборки приложения

`npm run check:bundle` SHALL проверять после `vite build` предел стартового графа в сыром виде, в gzip и в brotli, CSS первого экрана (сырой и gzip), суммарный размер precache и шрифтов в precache; превышение любого предела MUST завершать проверку с ошибкой, называющей метрику, значение и предел. Проверка SHALL записывать все измеренные значения в JSON по пути из `--json`, а CI в pull request SHALL выводить в сводку задачи таблицу «PR против `main`» с разницей.

#### Scenario: Превышение предела gzip

- **WHEN** gzip стартового графа больше предела
- **THEN** `check:bundle` завершается с ошибкой, называющей «gzip», измеренное значение и предел

#### Scenario: Сводка в pull request

- **WHEN** CI собирает pull request
- **THEN** сводка задачи `build` содержит таблицу размеров ветки и `main` с разницей по каждой метрике

#### Scenario: Сборка `main` недоступна

- **WHEN** сборка базовой ветки для сравнения не удалась
- **THEN** сводка отмечает, что сравнения нет, и проверка пределов продолжается без него

### Requirement: Lighthouse в CI

CI SHALL измерять Lighthouse на mock-сборке в мобильном профиле (150 мс, 1,6 Мбит/с, CPU ×4) тремя прогонами и сравнивать медианы с бюджетом: LCP выше 3 с — предупреждение, выше 4 с — ошибка; TBT выше 200 мс — ошибка; вес передачи выше 450 КиБ — ошибка. Отчёт SHALL называть число и вес чанков JS, которые первый экран грузит сверх стартового графа из HTML, а вес этих чанков выше предела MUST завершать задачу с ошибкой.

#### Scenario: LCP между порогами

- **WHEN** медиана LCP 3,5 с
- **THEN** задача проходит и выводит предупреждение с значением

#### Scenario: LCP выше предела

- **WHEN** медиана LCP больше 4 с
- **THEN** задача завершается с ошибкой

#### Scenario: Вес ленивых чанков выше предела

- **WHEN** первый экран грузит чанки JS сверх стартового графа тяжелее предела
- **THEN** задача завершается с ошибкой, называя чанки и вес

#### Scenario: Один выброс среди прогонов

- **WHEN** один из трёх прогонов заметно хуже двух других
- **THEN** решение принимается по медиане, а не по худшему прогону

### Requirement: Бюджеты контента

`npm run content` на настоящем контенте SHALL завершаться ошибкой, если пакет урока больше 40 КБ gzip, каталог больше 25 КБ gzip, пакеты курса вместе больше 1,6 МБ gzip, битрейт mp3 больше 32 кбит/с или файл mp3 больше 250 КБ. Тесты сборки на фикстурах MUST не зависеть от этих пределов.

#### Scenario: Раздутый пакет

- **WHEN** пакет урока после правки весит больше 40 КБ gzip
- **THEN** сборка контента падает с названием пакета, размером и пределом

#### Scenario: Аудио с высоким битрейтом

- **WHEN** в `media` добавлен mp3 с битрейтом выше предела
- **THEN** сборка падает с именем файла и битрейтом

#### Scenario: Курс в пределах

- **WHEN** все размеры в пределах
- **THEN** сборка печатает размеры и запас до пределов

### Requirement: Ночной замер под нагрузкой

Отдельный workflow SHALL ежесуточно и по запросу собирать mock-сборку на настоящем контенте и измерять с замедлением процессора ×4: время установки курса, TBT во время установки, p98 задержки отклика на нажатия во время урока. p98 выше 100 мс MUST завершать workflow с ошибкой; время установки и TBT SHALL публиковаться в сводке и артефакте без порога. Замер MUST не входить в обязательные проверки pull request.

#### Scenario: Задержка отклика выше предела

- **WHEN** p98 задержки отклика в уроке больше 100 мс
- **THEN** ночной workflow падает, сводка показывает p98 и число нажатий

#### Scenario: Замер не блокирует pull request

- **WHEN** открывается pull request
- **THEN** ночной замер не запускается и не входит в `checks`

### Requirement: Отчёт о длительности тестов

Прогон vitest в CI SHALL перечислять тестовые файлы дольше 10 с (для проекта `heavy` — дольше 60 с, считая импорт и окружение) в сводке задачи и предупреждением в логе; превышение само по себе MUST не ломать задачу.

#### Scenario: Медленный файл

- **WHEN** тестовый файл идёт дольше 10 с
- **THEN** сводка задачи называет файл и его длительность

#### Scenario: Тяжёлый файл в пределах 60 с

- **WHEN** файл проекта `heavy` идёт 30 с
- **THEN** предупреждения нет

#### Scenario: Все файлы быстрые

- **WHEN** ни один файл не дольше 10 с
- **THEN** предупреждений нет
