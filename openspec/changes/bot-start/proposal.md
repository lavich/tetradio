## Why

У @TetradioBot нет серверной части: `/start` и любые сообщения боту остаются без ответа (`docs/telegram.md:17`). Человек, нажавший Start, видит пустой чат и не получает кнопки, которая открывает приложение. Перед публичным запуском это первый контакт с продуктом (`public-launch-readiness`, раздел 2, вариант B).

## Требование пользователя

Решения пользователя 26.10.2026:

- «давай сначала start обработаем» — сначала ответ на `/start`; приём сообщений и обратная связь — следующим изменением.
- Выкатка — GitHub Actions.
- Адрес вебхука — `*.workers.dev`.
- На любое сообщение, кроме `/start`, — короткий ответ и кнопка: «Сообщения боту пока не читаются. Τετράδιο открывается кнопкой ниже.»
- Приветствие на `/start`: «Τετράδιο — греческий с нуля до экзамена A2: уроки по программе и ежедневное повторение слов. Прогресс переносится между устройствами вашего аккаунта Telegram.» и кнопка «Открыть Τετράδιο» (черновик принят, вторая фраза заменена после ревью плана по PRODUCT.md).

## What Changes

Предлагаемый объём:

- Cloudflare Worker в каталоге `bot/`: принимает обновления Telegram по вебхуку, проверяет секрет вебхука и отвечает в личном чате приветствием на `/start` (в том числе `/start <параметр>`) и коротким ответом на любое другое сообщение; у обоих ответов — кнопка, открывающая Mini App.
- Ответ отдаётся в теле ответа на вебхук: Worker не вызывает Bot API и не хранит токен бота.
- Выкатка Worker — job в `.github/workflows/deploy.yml` после зелёного CI на `main`, секреты Cloudflare — в GitHub Environment с правилом ветки `main`.
- Скрипт регистрации вебхука для однократного запуска владельцем с токеном бота из окружения.
- Документация: раздел о вебхуке в `docs/telegram.md`, исправление утверждений «обработчик `/start` и webhook не нужны».

Не входит: приём и пересылка сообщений автору, ответы пользователям, форма обратной связи, проверка `initData`, команды бота в меню, бот разработки.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `delivery`: бот отвечает на `/start` и на сообщения в личном чате кнопкой, открывающей Mini App; сбой ответа не влияет на работу приложения.

## Impact

- Новый каталог `bot/` (Worker, `wrangler.jsonc`, свой `package.json` и lock-файл с `wrangler`), тест `tests/bot-worker.test.ts`, скрипт `scripts/bot-webhook.ts` и его тест.
- `tsconfig.json`: `bot/worker.ts` в `include`; `.github/dependabot.yml`: зависимости `bot/`; `.gitignore`: `.wrangler/`. Корневые зависимости не меняются.
- `.github/workflows/ci.yml`: job сборки Worker; `.github/workflows/deploy.yml`: job выкатки Worker в GitHub Environment `cloudflare` с секретами `CLOUDFLARE_API_TOKEN`, `CLOUDFLARE_ACCOUNT_ID`; секрет Worker `WEBHOOK_SECRET`.
- Сообщения боту проходят через Cloudflare — это попадает в политику (`public-launch-readiness`, Б2); задача 1.5 того изменения («сообщение боту оставлено без ответа») меняется.
- Бандл приложения, лендинг, синхронизация и данные пользователя не меняются.
- `docs/telegram.md`, `README.md`.
