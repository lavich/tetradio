# Design

## Контекст

- `src/main.tsx` и `src/landing/main.ts` подключают `@fontsource-variable/literata` (`wght.css`, `wght-italic.css`) и `manrope`: fontsource отдаёт 7–8 `@font-face` с `unicode-range`, браузер тянет только файлы по реально используемым символам.
- Первый экран: `FirstRun.tsx` показывает подсказку после `useCatalog()`; цепочка — HTML → JS стартового графа (≈200 КБ gzip, из них ≈75 КБ не используются) → база Dexie → каталог из `window.__catalog` (#180).
- `main.tsx`: `setupServiceWorker()` вызывает `registerSW` сразу (тянет `workbox-window`); чанк `sync` грузится параллельно с базой и bridge (`Promise.all([database, import("./sync")])`).
- `vite.config.ts`: `workbox.globPatterns` берёт все `*-{latin,cyrillic,greek}-wght-*.woff2`, то есть и оба Latin-Literata (обычный 52 КБ, курсив 54 КБ).
- `app/index.html` уже запрашивает `catalog.json` из HTML; `scripts/check-bundle.ts` держит предел стартового графа (700 000 байт, замер deploy-сборки 583 884).

## Решения

### Шрифты и precache

Не меняются (решение пользователя 17.10.2026, см. proposal): Latin-Literata нужен английскому курсу, DESIGN.md требует Literata для напечатанного текста; выигрыш ≈0,15 с не стоит смены типографики. `@fontsource-variable` подключается целиком, как сейчас; `globPatterns` и состав precache не трогаются.

### Синхронизация и service worker

- Чанк `sync` сейчас грузят два места: `Promise.all([database, import("./sync")])` в `src/main.tsx` и `useSyncConflictSeen` в `src/app/deferred.ts` (вызывается из `App` при монтировании). Откладываются оба: проверка конфликта подписывается на `sync` после того, как отложенный импорт состоялся (общий промис загрузки чанка), а не импортирует сам.
- `registerSW` вызывается через `afterStartup` (`src/app/deferred.ts`: после `load`, пауза 2 с, затем `requestIdleCallback` с таймаутом 5 с). `dropServiceWorker` остаётся сразу: он снимает чужой service worker, задержка продлила бы его жизнь. До регистрации `updateReady.apply` остаётся пустышкой.
- Отложенный импорт `sync` для подключения облака запускается тем же `afterStartup`; `stop()` вызывает его функцию отмены, чтобы остановленный запуск не подгружал чанк. `launchSync` по-прежнему сверяет владельца до ожидания `connectSync`; `syncOnceOpened` отдаёт `skip`, если база не открылась.
- Раздел «Прогресс» (`/progress*`) подключает облако сразу (`syncNeededNow`): без адаптера проверка изменения облака при замене данных копией не выполняется (e2e `backup.spec.ts` курса это ловит).
- Выигрыш по замеру ≈0,03 с; решение пользователя — делать.
- Деградации: приложение, закрытое раньше паузы (до 7 с), не подключает облако в этот сеанс — прогресс остаётся локальным и уходит при следующем запуске; подписки на `pagehide` ставятся при подключении. Для e2e (`account.spec.ts`, `telegram.spec.ts`: ожидания 15–20 с) пауза не должна упереться в таймаут: проверка — `test:e2e` в трёх повторах; если пауза мешает, `delayMs` для `sync` уменьшается (например до 0 при простаивающем потоке).

### Стартовый граф

Разбор оставшегося: `course` (≈180 КБ: Dexie 96 КБ, ts-fsrs 61 КБ, схема контента 34 КБ, запросы и домен), `dexie-react-hooks` (на деле — `react-router`), `format` (`cn`-движок ≈42 КБ + база Button). Правило: рычаг оставляется, только если медиана LCP из трёх прогонов улучшилась или не ухудшилась при меньшем графе; иначе откат. Замена `cn`, разрезание Dexie/ts-fsrs по маршрутам и отдельный лёгкий путь первого запуска — вне объёма.

### check:bundle

К имеющимся проверкам (предел, SDK отчётов) добавляются: в стартовом графе нет чанков `sync`, `TelegramNotices` (диалог конфликта) и `workbox-window`. Предел `INITIAL_LIMIT` ставится по замеру после разбора графа, а не заранее.

### Замер

Протокол в `docs/perf.md`: `VITE_TELEGRAM_MOCK=1 npm run build`, `vite preview`, `lighthouse http://localhost:<port>/app/ --only-categories=performance` — мобильный профиль по умолчанию, три прогона, медиана; для рычагов — `--blocked-url-patterns`. В CI не входит (как `npm run perf`).

## Риски

- LCP до 2,5 с не достигается: фиксируется в итоге, не скрывается.
- Отложенный service worker: первое открытие после деплоя узнаёт об обновлении на 2+ с позже.
- e2e с облаком чувствительны к паузе (см. выше).

## Реализация

- Базовый замер (`main` после #180): Performance 0,85, FCP 2,80 с, LCP 3,65 с.
- Отложены оба загрузчика `sync`: подключение облака (`main.tsx`) и слежение за конфликтом (`useSyncConflictSeen`) через общий `loadSync()` в `deferred.ts`; `registerSW` — через `afterStartup`; `dropServiceWorker` остался сразу. `stop()` отменяет отложенную загрузку.
- Итог замера: Performance 0,87, FCP 2,70 с, LCP 3,45 с (−0,20 с в замере, но блокировка запросов обещала −0,03 с: разницу считать шумом трёх прогонов).
- Разбор стартового графа (3.1): безопасных рычагов без смены поведения не нашлось — `course` (Dexie, ts-fsrs, схема каталога) и `react-router` нужны запуску, а `cn` и разрезание по маршрутам вне объёма. Дальше — только отдельный лёгкий путь первого запуска (см. «Что осталось» в `docs/perf.md`).
- `INITIAL_LIMIT` 700 000 → 620 000 (граф на deploy-сборке 592 461).
- Находки ревью кода: отказ чанка до `connect` оставался необработанным (теперь `launchSync` гасит его, тест); облако для «Прогресса» без паузы (см. выше).
- Отклонение от плана: ревью плана нашло, что Latin-Literata нужен курсу «Английский для IT»; шрифты и precache не менялись (решение пользователя 17.10.2026).
