## Goals / Non-Goals

**Goals:**
- Начать второй и следующий курс с «Курса» без прямых адресов; начать курс — только кнопкой.
- Стартовый экран по брифу: группы языков, карточка курса из данных курса, «Готовится».
- «Слова», «Чтение», «Прогресс» никогда не остаются без курса из-за выбора на «Курсе».
- Первый начатый курс — первый в порядке, основной и домашний на любом новом устройстве; порядок без начатых курсов задаётся данными курса, а не алфавитом файлов.

**Non-Goals:**
- Переключатель языка, полки курсов одного языка, общий словарь языка — изменение (в).
- Пауза курса и раздел «Курсы» в «Настройках и данных» — изменение (б).
- Файл курса `english-travel` и его уроки — (в).
- Синхронизация основного курса и порядка между устройствами: формат облака в (а) не меняется.
- Исправление уже записанных порядка и домашнего курса на устройствах, где английский встал первым (см. Risks).
- «Учить курс» на «Сегодня», когда курс уже начат: начинать новые курсы — с «Курса».

## Decisions

### 1. Выбор полки отдельно от выбора начатого курса

Ключ `meta` `currentCourse` остаётся общим выбором и может хранить неначатый курс — его ставит только переключатель «Курса». Новый ключ `currentStartedCourse` хранит последний выбранный начатый курс и только начатые курсы. Три чтения:

- `selectedCourse()` — сохранённое значение `currentCourse` как есть.
- `shelfCourse()` — для «Курса»: `selectedCourse()`, если курс есть в `courses()`, иначе `currentCourse()`.
- `currentCourse()` — для «Слов», «Чтения», «Прогресса» и прочих вызовов: `selectedCourse()`, если начат; иначе `currentStartedCourse`, если начат; иначе основной. Это продолжение сегодняшнего правила (`src/storage/courses.ts:139`) с одним шагом перед основным.

`setCurrentCourse(id)`:
- курс начат — пишет `currentCourse` и `currentStartedCourse`;
- курс не начат — если сохранённый `currentCourse` начат, сначала пишет его в `currentStartedCourse` (всегда, не только при пустом ключе: так цепочка «начатый → неначатый → начат → неначатый» помнит последний начатый), затем `currentCourse`.

Когда выбранный неначатый курс начат, `currentCourse` уже указывает на него — все четыре экрана переходят на него сами, без записи в момент чтения. Пока `currentCourse` начат, второй ключ не читается, а при следующем выборе неначатого курса он получает этот курс.

`useFollowCourse` и лист «Чтение» сравнивают с `selectedCourse()`, а не с `currentCourse()`: иначе при выбранном неначатом курсе открытие модуля основного курса ничего бы не записало (`currentCourse()` уже равен основному), и полка осталась бы на карточке неначатого.

Альтернативы:
- *Один ключ, неначатый выбор падает на основной* — выбор английского на «Словах» терялся бы после взгляда на неначатый курс на «Курсе».
- *Выбор неначатого курса только в памяти экрана* — после перехода на другую вкладку полка возвращалась бы к прежнему курсу посреди загрузки.
- *Отдельный ключ для неначатого выбора, очищаемый после начала* — требует записи в момент, когда курс стал начатым, то есть из чтения или из установки.

### 2. Порядок курсов: место в данных и время начала

**Место.** Новое поле файла курса `order`. Сборка проверяет его (целое больше нуля, без повторов) и кладёт курсы в каталог по нему, курсы без `order` — после, по id. Клиент хранит `order` у курса; `courses()` ранжирует неначатые курсы по `order`, затем по месту первого урока в каталоге. Так стартовый экран, переключатель «Курса», основной и выбранный по умолчанию при нуле начатых — греческий (1), английский IT (2), английский для путешествий (3). Альтернатива — порядок в манифесте сборки: отдельный файл для одного числа на курс; поле рядом с остальными данными курса проще проверять и читать.

**Время начала.** `rememberCourses` считает курс начатым для порядка, если его уроки есть на устройстве или ждут установки из снимка (`sync:pendingLessons`, курс — по записи каталога, как в `syncCourses`). Новые для порядка курсы встают в конец `coursesOrder` по самой ранней дате `updatedAt` своих уроков (на устройстве и в ожидающих), при равных или без дат — по `order`. Домашний курс, если не записан, — первый из получившегося порядка. Записанные `coursesOrder` и `homeCourse` не перезаписываются: дописываются только новые курсы.

`updatedAt` неначатого урока — время его установки (`src/content/apply.ts:107-113`), пройденного — время прохождения; самый ранний урок курса — момент его начала. Даты уроков снимка уже есть (`src/sync/snapshot.ts:92-96`), формат не меняется.

На новом устройстве после применения снимка оба курса сразу в ожидающих, первый же вызов `rememberCourses` (после первого установленного урока любого курса) записывает «греческий, английский» и домашний греческий. `primaryCourse()` уважает только начатые курсы, поэтому, пока ставятся первые английские пакеты, основным может кратко быть английский — до первого греческого урока; запись порядка и домашнего от этого не зависит.

Альтернатива — синхронизировать порядок и основной курс: поле снимка и изменение формата, которое бриф относит к (б).

### 3. Стартовый экран: курсы начинаются по одному

Пока ставится первый урок нажатого курса, «Учить курс» у остальных курсов недоступна с пояснением «Сначала загрузится «<название>»». После первого урока стартовый экран сменяется «Сегодня» курса; после ошибки до первого урока кнопки снова доступны, а `coursesOrder`, `homeCourse` и `primaryCourse` не записаны — их пишет только установленный урок.

Так первый нажатый курс — первый установленный и по `rememberCourses` первый в порядке, основной и домашний, без отдельного ключа намерения. Альтернатива — записывать основной при нажатии: при неудачном офлайн-нажатии выбор оставался бы и позже срабатывал без ведома учащегося, а порядок и домашний курс всё равно расходились бы.

### 4. Переключатель в двух видах и короткое имя

`CourseSwitch` получает вид: на «Курсе» — `courses()` целиком, значение — `shelfCourse()`; на остальных экранах — только начатые, значение — `currentCourse()` (как сейчас). Вариант называется полем `short`, без него — названием. Неначатый вариант: видимый текст «+ Имя», где «+» скрыт от экранной читалки, `aria-label` «Имя, не начат». На «Курсе» переключатель есть, когда в `courses()` больше одного курса; на остальных — когда начатых больше одного. Курс без опубликованных уроков в `courses()` не входит и в переключатель не попадает.

Порядок вариантов — `courses()`: начатые по порядку начала, затем неначатые по `order`. После начала курс встаёт последним среди начатых; при двух курсах его место не меняется, при трёх и больше он может подняться выше неначатого, стоявшего перед ним.

`short` — поле файла курса, а не сокращение в коде: «Английский для IT» в переключателе (а) — «Английский»; в (в) переключатель становится языковым, и короткое имя языка берётся из профиля языка.

### 5. Полка и модуль неначатого курса — карточка

`CourseScreen` берёт `shelfCourse()`; неначатый курс — «Полка», переключатель и карточка курса (`CourseOffer`) вместо обложек и строки экзамена. Это же закрывает случай «ноль начатых — обложки неначатого курса».

`ModuleScreen` модуля неначатого курса показывает ту же карточку вместо оглавления и не ставит уроки: курс начинается только кнопкой, и порядок начала не зависит от того, что открыто по адресу. Помощник e2e `openModule` начинает курс через «Учить курс» на полке.

Курс начат, как только на устройстве есть его урок; во время загрузки остальных уроков полка показывает обложки. Ошибку загрузки остальных уроков полка не показывает: она видна на экране модуля при его открытии (`ModuleScreen.tsx:41-42`), а `syncCourses` догружает курс при следующем запуске. Так ведёт себя и «Учить курс» на «Сегодня» сейчас: после первого урока экран сменяется, фаза ошибки курса больше не видна. Альтернатива — строка ошибки над обложками с «Повторить»: второй источник состояния загрузки рядом с полкой и новый текст; при сети, вернувшейся к следующему запуску, она не нужна.

### 6. Данные карточки курса

Поля файла курса `level`, `goal`, `short`, `order` — имена в стиле существующих (`passShare`, `calendar`). Нагрузки на карточке нет (решение пользователя 20.10.2026), поля для неё нет.

Разбор полей — в `src/content/course.ts` рядом с `parsePassShare`, общий для сборки и `parseCatalog`. Шаблон уровня — `^(A0|A1|A2|B1|B2|C1|C2)\+?( → (A1|A2|B1|B2|C1|C2)\+?)?$` после NFC; стрелка — только « → ». Цель — одна фраза без перевода строки, до 90 символов; «одной строкой» в брифе — одна фраза: на 360 px она переносится и занимает не больше двух строк карточки (проверяется снимком на утверждённых текстах). `short` — до 14 символов: два варианта с «+» помещаются в 360 px без многоточия (проверяется снимком). `order` — уникальность проверяет сборка по всем курсам.

`CatalogCourse` и `Course` получают `level?`, `goal?`, `short?`, `order?`; `Course` ещё `language?` — язык курса из каталога (пустая строка — нет языка), чтобы курс без уроков («Готовится») попал в группу своего языка. `adoptCourses` сравнивает и переносит новые поля. Dexie не меняется: `courses` индексирован только по `id` (`src/storage/db.ts:85`).

Объём не хранится в файле курса: число модулей и опубликованных модулей курса берётся из `db.modules` (кеш каталога, черновики в нём есть). Склонение: «готов 1», «готовы 2», «готово 5». Курс из списка уроков без модулей (фикстура `mechanics`) показывает «N уроков», как сейчас.

`SCHEMA_VERSION` каталога не меняется: поля необязательные, прежний клиент их пропускает.

### 7. Стартовый экран и карточка

`TodayScreen` при пустом `db.packages` показывает `h1` «Τετράδιο» с `lang="el"` (`data-testid="today-title"` сохраняется), строку о приложении и `FirstRun`. Курсы для карточек — строки `db.courses`, у которых в текущем каталоге есть записи уроков или модули (`db.catalog`, `db.modules`): курс, убранный из каталога, не показывается, «Готовится» показывается. Группы — по `Course.language`, при его отсутствии — по языку записей уроков; группы и курсы внутри — по `order`, затем по месту в каталоге. Заголовок группы — `h2` из `profile.names.title` («Греческий», «Английский»), только при двух языках и больше; название курса в карточке — `h3` (без групп — `h2`).

Карточка (`CourseOffer`): заголовок «Название · уровень»; цель; строка объёма; кнопка «Учить курс» или пометка «Готовится» (курс без записей уроков в каталоге). Ошибка установки и «Повторить» — как сейчас (`FirstRun.tsx:56-65`). Подсказка «Уроки загрузятся на устройство и будут доступны без сети» остаётся под кнопкой. Широкий экран — одна колонка карточек, как полки в брифе.

### 8. Синхронизация не меняется

Новый ключ `currentStartedCourse` — `meta` базы аккаунта, как `currentCourse`: снимок его не читает, в локальную копию данных он входит вместе с прочими ключами курса. Поля карточки — из каталога. Начатые курсы на новом устройстве ставит, как сейчас, синхронизация (`installPackages` по недостающим пакетам снимка) и `syncCourses` при следующих запусках; меняется только то, как `rememberCourses` упорядочивает уже начатые курсы.

## Risks / Trade-offs

- [Уже записанный неверный порядок] → на втором устройстве, где английский курс уже встал первым и домашним, порядок и домашний курс не чинятся автоматически: переписывать домашний курс опаснее — данные без курса сменили бы язык. Основной курс учащийся меняет в «Настройках и данных». Тест: записанные `coursesOrder` и `homeCourse` не перезаписываются.
- [Основной кратко английский на новом устройстве, пока не встал первый греческий урок] → порядок и домашний курс записаны верно с первого урока; `primaryCourse()` выправляется сам с первым греческим уроком.
- [Стартовый граф растёт: «Сегодня» без уроков — первый экран] → `npm run build && npm run check:bundle`; если предел превышен — замер и поднятие предела отдельной строкой с числами в «Реализация».
- [`english-it` начинается с одного готового модуля] → объём «16 модулей, готов 1» говорит об этом до нажатия; курс уже в каталоге с одним модулем.
- [Экран модуля больше не ставит уроки неначатого курса] → ссылок на модули неначатых курсов в приложении нет; e2e-помощник переходит на кнопку; поведение для начатого курса прежнее.
- [Фикстура `two-courses` получает третий курс] → курс из одного чернового модуля не входит в `courses()`, поэтому переключатели, «Сегодня» и порядок курсов в существующих тестах не меняются; полный прогон `test:e2e:courses` и `tests/two-courses*.test.ts` это проверяет.

## Migration Plan

- Данные не мигрируют. У существующего учащегося `currentStartedCourse` пуст до первого выбора неначатого курса; при нём записывается сохранённый начатый выбор (решение 1). Записанные `coursesOrder` и `homeCourse` не меняются.
- Каталог с новыми полями совместим с прежним клиентом; новый клиент с прежним каталогом показывает карточки без уровня и цели и порядок по месту в каталоге.
- Откат — возврат кода; ключ `currentStartedCourse` прежней версией не читается.
