## Context

`buildMatcher(cards, profile)` разбирает каждую карточку, выводит формы и кладёт шаблоны в `Map` по первому токену. В `readings.ts` его вызывают для карточек уроков до открывающего (`coverage` → `coverer`, затем ещё раз, `:320`); в `questions.ts` `coverer` создаётся на каждый урок с вопросами по накопленным карточкам курса; `mark-courses.ts` уже строит один сопоставитель на курс и фильтрует рангом — этот шаблон и переносим. Префиксность набора (карточки урока 0…N, порядок как в курсе) делает отсечение точным.

## Goals / Non-Goals

**Goals:** сборка < 2 с; побайтно тот же результат; один сопоставитель и словарь на курс.
**Non-Goals:** менять правила разметки, покрытия, пороги; кэш между запусками; ускорять озвучку, медиа и чтение файлов (≈1 с на I/O).

## Decisions

1. **`at` на шаблоне.** `MatchCard.at?: number`, `Pattern.at`. `candidates(text, matcher, upto = Infinity)` пропускает шаблоны с `at > upto`. Порядок шаблонов в списке — порядок карточек курса, а отфильтрованный префикс сохраняет порядок, поэтому `choose` (сортировка устойчивая) видит тех же кандидатов в том же порядке. Ключ `seen` содержит `ref`, значит, дедупликация не зависит от соседних карточек.
2. **`skipped` остаётся `string[]` по всему курсу:** единственный потребитель — `mark-courses`, где отсечения нет.
3. **`coverer` с отсечением.** `surfaces: Map<string, number>` — минимальный `at` поверхности (карточки, формы, глоссы урока, знакомые строки); `stems` — массив `[основа, at]`. Возвращаемая функция принимает `upto`; `known`/`stems` фильтруются по `at <= upto`. Глоссы и «знакомые строки» уроков получают `at` своего урока. Основы по отсечению отбираются без пересортировки: порядок не влияет на результат (`some`).
4. **Значения по умолчанию и нумерация.** `at ?? 0`, `upto = Infinity`: тесты без `at` работают как раньше. `at` — позиция урока в `course.lessonIds`, одинаково везде. Общий сопоставитель и словарь строятся один раз на курс в `build.ts` и передаются в `markCourses`, `buildReadings`, `checkQuestions`.
5. **Отсечение в `lessonMarks`.** `LessonMarksInput.upto` пробрасывается в `candidates`; `rank` в `readings.ts` дополнительно возвращает `undefined` для `introduced.at > at`: общий `introduced` иначе дал бы карточкам будущих уроков отрицательный ранг.
6. **Бюджет.** `isGreekLetter`/`isLetter` — результат по символу в кэше вместо регулярки на каждый вызов (в профиле ≈1,3 с self-time вместе с `norm`/`tokenize`), `norm` с мемоизацией по строке. Профиль: `coverer` и `buildMatcher` ≈3 с из ≈4; убрав повторные сборки, остаётся ≈2 с, резервы — токенизация.
7. **Вызывающий код.** `readings.ts`: карточки и `introduced` строятся один раз на курс (сейчас — на текст); текст задаёт `upto = индекс урока after`. `questions.ts`: один `coverer` на курс, `upto` = индекс текущего урока; поле `known` (шпаргалка модуля, формы слов) получает `at` урока, в котором добавлено.
8. **`existing` → `Set`.** В `planAnswerVoices` и `planReadingVoices` (на время `npm run content` не влияет: вызываются скриптами озвучки); интерфейс (`string[]`) сохраняем, `Set` строится внутри.
9. **Проверка равенства.** Юнит-тест: на реальном курсе для каждого урока список мест и покрытие отсечением равны сборке по префиксу (старый путь остаётся в тесте как эталон). Плюс хеш `public/content` до/после; `generatedAt` в `catalog.json` исключается (меняется при каждом запуске). `stems` держим по возрастанию `at` и берём срез по `upto`, без аллокации на вызов.

## Risks / Trade-offs

- Тонкая разница порядка при равных кандидатах — закрыта тестом равенства и хешем.
- Растёт память словаря курса (один набор вместо серии растущих) — ожидаем падение, не рост; проверить `/usr/bin/time -l`.
- Правки пересекаются с #156/#157 только по тестам и CI-скриптам: их файлы не трогаем.

## Реализация

- Замер на `main` 4dbf0dc: 3,9–5,6 с, RSS 460–500 МБ. После: 1,7–1,8 с, RSS ≈360 МБ; хеш `public/content` (без `generatedAt`) и вывод сборщика совпадают. В профиле остались `open`/`rmSync`/запись файлов (≈1 с): цель «меньше 2 с» достигнута, дальше — вне сопоставителя.
- Отклонение от п. 6: диапазоны кодов не понадобились — мемоизация по символу и `norm` дала тот же результат.
- `introduced` общий на курс, `rank` в `readings.ts` отсекает `at > после` (п. 5).
