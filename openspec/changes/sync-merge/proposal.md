## Why

Окно «Прогресс разошёлся между устройствами» требует от учащегося выбрать одну версию целиком; ответы другой откладываются. После `sync-reliability` (#325) окно появляется только при настоящем расхождении — занимались на двух устройствах, и одно не успело отправить ответы, — но и тогда учащийся не может осмысленно выбрать: обычно на обоих устройствах сделано нужное. Issue #324.

## Требование пользователя

29.10.2026: «а автомерж можно сделать после правок? … то есть ответов» → «да» (заведена задача #324); «делай #324». После ревью плана (оценка выросла до 2,5–3 недель) — «делать».

Решения по открытым вопросам приняты по рекомендации — **рекомендация, пользователь может изменить до реализации**: (1) карточка изменена на обоих устройствах — состояние с более поздним ответом (время — часы устройства); (2) слияние тихое, снимок до слияния хранится в «Отложенных версиях облака» как страховка, по числу (последние 5 отвергнутых); (3) версии двух других устройств (`remote`) сливаются при общем предке, иначе окно.

## What Changes

Предлагаемый объём:

- Устройство хранит **цепочку предков** — последнюю применённую или слитую версию и свои публикации после неё — закодированным текстом в локальной таблице `syncVersions` (роль `ancestor`). Для расхождения берётся самый поздний предок, от которого происходят все ветви и после которого они не делят историю.
- При расхождении версий с общим предком координатор **сливает** их (предок / здесь / облако) по правилам для каждого поля снимка, применяет результат, оставляя отметку изменений, и публикует его обычной публикацией как версию, покрывающую все ветви (`resolves`). Сбой между применением и публикацией ответов не теряет. Окна выбора нет.
- Правила слияния детерминированы и симметричны (ничьи — по содержанию): результат не зависит от того, какое устройство сливает. Одновременное слияние на двух устройствах сходится без окна и без лишних публикаций: версия облака с тем же содержанием принимается без публикации.
- Окно выбора остаётся для расхождений без общего предка: `initial`, `restored`, версия облака не происходит от предка, предка ещё нет (первый обмен после обновления).
- Формат облака не меняется: результат слияния — обычный снимок форматов 5/6; прежние версии приложения применяют его как обычную версию.
- Тесты: свойства слияния, рандомизированный тест чередований на 2–3 устройства с инвариантами (ответы не теряются и не удваиваются, публикаций конечное число), сценарии почти одновременной публикации, потерянного ответа облака, сбоя между применением и публикацией, прежняя сборка рядом. Существующие тесты, ждущие окно в этих случаях, переписываются явно.

Не входит: история ответов в облаке и точный пересчёт FSRS по объединённой истории (истории в облаке нет); слияние без общего предка.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `account-sync`: «Надёжная синхронизация» — автоматическое слияние расхождений с общим предком; окно выбора — только без предка.

## Impact

`src/sync/coordinator.ts` (решение, сходимость, слияние, продвижение цепочки предков во всех путях публикации), новый `src/sync/merge.ts` (чистая функция слияния снимков), `src/sync/snapshot.ts`, `src/sync/types.ts` (роль `ancestor`), `src/features/backup/backup.ts` (восстановление очищает цепочку в своей транзакции), «Отложенные версии облака» (без предков), `docs/sync.md`, тесты `tests/sync-merge*.test.ts` и пересмотр ожиданий существующих тестов синхронизации. Формат облака, схема IndexedDB и копия данных не меняются. Оценка — 2,5–3 недели.
