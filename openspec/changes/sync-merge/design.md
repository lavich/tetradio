## Решения

### 1. Цепочка предков

Один предок «последняя синхронизированная версия» ошибается в двух частых случаях: обе стороны опубликовали почти одновременно (предок телефона — его собственная публикация, которую версия компьютера не покрывает → окно), и потерянный ответ облака (часы сдвинуты на версию X, снимка X нет → изменения X−A считаются дважды, `L + R − A` удваивает статистику).

Поэтому устройство хранит **цепочку предков**: последнюю применённую или слитую здесь версию и свои публикации после неё. Для набора ветвей облака предок — **самый поздний** снимок цепочки, часы которого покрывает каждая ветвь (`dominates(branch.clock, ancestor.clock)`), и при этом поэлементный минимум часов ветвей (включая локальную) равен часам предка — иначе ветви делят историю после предка и `L + R − A` удвоит её; тогда окно.

Как пишется и продвигается:

- **Применение** версии облака (`applySnapshot`) — цепочка заменяется этой версией, в одной транзакции с `sync:applied`/`sync:clock`.
- **Публикация** — снимок пишется в `beforeWrite` в одной транзакции с `sync:publishing` (до записи частей); при подтверждении, в `settlePublishing` и в `nothingUnpublished` — становится последним звеном. Неподтверждённая публикация (части без указателя) из цепочки удаляется вместе с `sync:publishing`.
- **Слияние** — цепочка заменяется результатом после его публикации (см. 3).
- **Инвариант**: часы последнего звена равны `sync:clock`. Если нет (сбой между транзакциями прежних сборок, ручное вмешательство) — предка нет, окно.
- Цепочка обрезается: звенья, которые покрывают часы всех известных указателей облака, кроме последнего, удаляются при уборке. На практике — 1–3 звена.

Хранение: строки `syncVersions` с ролью `ancestor`, id `ancestor-<номер>`; содержимое — **закодированный текст формата 6** (`encodeSnapshot` + `packSnapshot`, `src/sync/codec.ts:274`, `src/sync/compression.ts:21`), около 0,5 МБ на бюджете вместимости (`docs/sync.md`, «Вместимость»; несжатый объект — 1,3–1,9 млн символов). Запись — одна строка при каждой публикации (по ходу занятия — не чаще раза в 2 минуты); чтение — только при расхождении. Кодек заодно нормализует снимок для сравнения (M1). Id не совпадают с id поколений и уборку облака не защищают; `listStored` фильтрует роль `ancestor` (в «Отложенных версиях облака» её нет). Схема Dexie не меняется (роль — строковое поле); тип `SyncVersionRow` получает вариант с `packed: string` вместо `snapshot`.

Восстановление копии и удаление данных удаляют цепочку: таблица `syncVersions` входит в транзакцию восстановления (сейчас она в `skipTables`, `backup.ts:36` — для чтения копии это остаётся, но очистка цепочки идёт в той же транзакции). После восстановления — конфликт `restored`, как сейчас.

Варианты: (а) строки `syncVersions` — выбрано: без новой таблицы и миграции, вне копии; (б) ключ `meta` — входит в копию, мешает чтению `meta`; (в) брать предка из облака — его прежнее поколение уже убрано уборкой.

### 2. Правила слияния (`src/sync/merge.ts`, чистая функция)

`merge(ancestor, branches[])` → снимок. Все снимки сравниваются **после прогона через кодек** формата ветви (как `sameProgress`), чтобы умолчания кодека (`learning_steps ?? 0`, `src/sync/codec.ts:118`) не давали ложных «изменили обе». Общее правило для любого поля: если все изменившие стороны пришли к одному значению — оно. Иначе: изменила одна сторона — её значение; несколько — правило поля. **Ничьи** (равные времена и т. п.) разбиваются по содержанию: побеждает значение с большей JSON-строкой — не по id ветви, у одной ветви разные id на разных устройствах (`local-<device>` и `<device>-N`). Правила симметричны: результат не зависит от того, какое устройство сливает и в каком порядке ветви.

| Поле | Изменили несколько сторон |
| --- | --- |
| `states[ref]` (FSRS, в т. ч. `cardStash`, незнакомые виды) | состояние с более поздним `card.last_review` (решение 1); `version` = max + 1; `introducedAt` = min |
| `states[ref]` удалена одной стороной, изменена другой | изменённая |
| `lessons[id]` | `completed` = или; `updatedAt` = max |
| `blocks[lesson, block]` | блок **целиком** с более поздним `updatedAt` — сохраняет «Повторить» (`done: false`, без счёта) и не даёт `done` без счёта |
| `packages` | объединение |
| `skills[ref].types[type]` | у более позднего `lastAt` (последние 10 исходов этого типа — одной стороны; см. «Риски») |
| `skills[ref].cleanAssemblies` | если хоть одна сторона меньше предка (был сброс ошибкой) — минимум сбросивших сторон; иначе `L + R − A`; не ниже 0 |
| `skills[ref].lastTypes` | у стороны с более поздним `lastAt` по карточке |
| `stats.days[date]` | `answers` = сумма приростов сторон к предку + предок (n-арное `Σ(Xᵢ − A) + A`), не ниже 0; `keys` = объединение; окно `KEEP_DAYS` |
| `stats.answers` | `Σ(Xᵢ − A) + A` |
| `stats.answeredKeys`, `reviewDays` | объединение |
| `stats.recentByType[type]` | у стороны с более поздним ответом этого типа (по `skills.lastAt`) — приближение |

**Удаление.** Отсутствие значения у стороны — удаление, только если её формат это значение выражает: ветвь форматов 3/4 или без `rd` не удаляет незнакомые виды карточек и дни повторений; уроки и блоки удаляются только явным отсутствием при формате, где они есть. Незнакомые поля и типы формата 5 переносятся как непрозрачные значения по ключу.

`L + R − A` и `Σ(Xᵢ − A) + A` корректны только при правильном предке (1): поэлементный минимум часов ветвей равен часам предка, значит, никакое изменение после предка не входит в две ветви.

### 3. Координатор

В `decide` вместо конфликта `diverged`/`remote`:

1. **Равное содержание без отметки (сходимость, B3).** Если отметки изменений нет и содержание кандидата после кодека равно локальному (без `createdAt` и `packages`) — принять `mergeClocks(свои, кандидата)` и `applied` = кандидат, без публикации и без окна. Это закрывает одновременное слияние на двух устройствах: оба получили одинаковое содержание с разными часами; следующий обмен у каждого принимает чужие часы, публикаций больше нет.
2. **Слияние.** Если есть предок для всех ветвей (1) — `merge(ancestor, [local, ...remote])`. Результат применяется одной транзакцией поверх локальной базы (отметка изменений должна совпасть с прочитанной при сборке локального снимка, иначе — решать заново) с часами `mergeClocks(все ветви)` и **новой отметкой изменений** — применение не делает устройство «чистым» (B2). Затем обычная публикация (сборка снимка из базы, `override = null`, отметка — прочитанная при сборке, `resolves` = id ветвей облака). Сбой между применением и публикацией оставляет отметку: следующий обмен публикует результат (его часы покрывают ветви) — ответы не теряются.
3. **Без предка** — окно, как сейчас.

Три устройства и `remote`: сливаются, если для всех ветвей есть общий предок по правилу 1 (решение 3); иначе окно.

Ошибка в `merge` (исключение) — конфликт, как раньше, с отчётом об ошибке; данные не меняются.

### 4. Формат облака

Не меняется. Результат слияния — обычный снимок форматов 5/6 с `resolves`. Прежние версии приложения без отметки применяют его как версию, покрывающую их собственную; с отметкой — показывают окно (их поведение). `tests/sync-format-compat.test.ts` проходит без изменений.

### 5. Что видит учащийся

Слияние тихое: статус «Синхронизировано» (решение 2). Локальный снимок до слияния сохраняется в «Отложенных версиях облака» строкой роли `rejected` с подписью «До объединения <дата и время>» — страховка; уборка хранит, как остальные отвергнутые, последние `KEEP_REJECTED = 5` по числу (не по сроку). Окно остаётся для `initial`, `restored`, ветвей без общего предка и ошибок слияния.

## Тесты

- **Свойства `merge`** на сгенерированных снимках с фиксированным зерном: `merge(A, [X]) = X`; `merge(A, [A, X]) = X`; `merge(A, [X, X]) = X`; симметрия по порядку ветвей; `stats.answers` = `A + Σ(Xᵢ − A)`; завершённые уроки не теряются; `cleanAssemblies` не отрицательный.
- **Рандомизированный тест чередований** (2–3 устройства, фиксированное зерно, сотни прогонов): шаги — ответы (практика и плановые), задания урока, обмен, потеря ответа облака на записи указателя, сбой между применением слияния и публикацией, перезапуск. Инварианты в конце (все устройства обменялись до тишины): одинаковое содержание у всех; итоговое `stats.answers` равно числу записанных ответов; все пройденные уроки на месте; окна нет, кроме сценариев без предка; число публикаций конечно (нет бесконечного обмена).
- **Сценарии**: почти одновременная публикация (B1); потерянный ответ облака + слияние (без удвоения статистики); сбой между применением и публикацией (B2); одновременное слияние — сходимость без лишних публикаций (B3); `cleanAssemblies` со сбросом на одной стороне; блок «Повторить» против выполненного; ветвь формата 4 / без `rd` не удаляет; три устройства; `remote`; восстановление копии посреди слияния; прежняя сборка рядом.
- **Меняемые ожидания существующих тестов** (сейчас ждут окно, после изменения — слияние): `tests/sync-reliability.test.ts:165,187,230`, `tests/sync-coordinator.test.ts:248,348`, `tests/sync-course-pause.test.ts:272`, `tests/sync-review-days.test.ts:216-249`. Каждое ожидание переписывается явно: окно → слияние (или остаётся окно, если в сценарии нет предка — тогда тест получает комментарий-причину в названии).

## Риски

- **Одна карточка на обоих устройствах**: «позже побеждает» теряет влияние ответа другой стороны на интервал (ответ остаётся в навыках и статистике). Время — часы устройства: устройство со спешащими часами выигрывает всегда; записать в `docs/sync.md`.
- **Скользящие окна** (`recentByType`, `recent[]` навыка) — приближение: исходы одной стороны в окне теряются, если обе отвечали одну карточку одним типом. Счётчики и дни — точны.
- **Предок устаревает**, если устройство долго не синхронизировалось, а другие выбирали версии окном или ветви делят историю после предка: окно, как раньше.
- **Объём**: цепочка предков — 1–3 строки по ~0,5 МБ в IndexedDB; запись при каждой публикации.
- **Сложность координатора**: новые ветви решения; рандомизированный тест — главная защита.

## Открытые вопросы

Решения 1–3 приняты по рекомендации — **рекомендация, пользователь может изменить до реализации**:

1. Одна карточка изменена на обоих устройствах — состояние с более поздним ответом (с оговоркой про часы устройства).
2. Слияние тихое; снимок до слияния — в «Отложенных версиях облака», по числу (`KEEP_REJECTED = 5`).
3. Конфликт `remote` — сливать при общем предке всех ветвей, иначе окно.
